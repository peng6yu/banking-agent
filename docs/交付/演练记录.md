## 三、发现的不一致（按严重度分级）

### 中 · 健康检查的预期块过期

`docs/演示脚本.md` 零、第 4 步写「预期：`{"ok":true,...,"tools":10,...}`」，实测返回 `"tools":26`，且额外带 `now_ms`、`sessions` 两个字段。工具已从 10 个扩到 26 个，预期块没跟着改 —— 照着文档核对的人会以为服务起错了。

### 中 · 健康检查的 `model` 字段不反映当前生效的适配器

离线跑 `MOCK_MODE=script` 时 `/api/health` 仍返回 `"model":"MiniMax-M3.1-Flash-Preview"`。现场若靠这个字段判断「用的是真模型还是桩」，会判断反。建议现场以「是否联网 + 启动命令里的 MOCK_MODE」为准。

### 中 · 操作 G 的口播事件链顺序与实测不一致

文档写 `session.start → intent.parsed → dag.built → …`，实测本轮真实顺序是：

```
intent.parsed → session.start → dag.built → policy.decided → tool.executed
→ policy.decided → tool.executed → policy.decided → confirm.requested
→ confirm.approved → token.issued → transfer.initiated → transfer.committed
→ tool.executed → session.end
```

意图解析发生在会话开始之前（先解析，拿到结果才开会话）。**照着面板念口播要按实测顺序念**，别按文档念。

### 中 · 断网兜底只覆盖三幕，红灯与账单跑不出来

两个桩语义完全不同，现场必须分清：

| 桩 | 启动方式 | 能演什么 | 不能演什么 |
|---|---|---|---|
| 协作桩 | `MOCK_MODE=script` | 绿灯查余额、黄灯转账（含确认卡） | 账单分析、红灯多因子、同名澄清 —— 桩只认「余额」「转+金额」两种话术，其余诚实回 unknown |
| 对抗桩 | `MOCK_MODE=true` | 操作 F：恶意模型也动不了钱 | 任何正常业务 —— 它会把每句话都变成恶意计划 |

结论：**断网时只能演 黄灯转账 / 对抗拦截 / 审计回放 三幕**；账单与红灯两幕必须在有网可用时演。这条要写进现场应急预案，别到台上才发现。

### 轻 · `python3.12` 依赖 PATH

文档里所有命令都用裸 `python3.12`。本机它在标准 PATH 内（`/home/peng/.local/bin/python3.12`），实测可直接用；但最小化 shell 里会 `command not found`。开演前建议先 `export PATH=$PATH:/home/peng/.local/bin` 一行兜住。

### 轻 · 审计校验样例的 count 是旧快照

文档样例写 `"count":122`，实测新库返回 `22`（本次演练库）。结构一致（`ok`/`head`/`count`），现场念数字要读实际返回值，不要念文档里的样例值。

## 四、刷新恢复现场：现在是真的（t12 修复后首次实测）

`GET /api/session/s_rehearsal` 在确认卡等待期间返回：

```json
{"status":"active","confirmations":[{"confirmation_id":"cf_59b7c8eb","node_id":"n3","status":"pending"}]}
```

批准后再查：`{"status":"done","confirmations":[{"confirmation_id":"cf_59b7c8eb","node_id":"n3","status":"approved"}],"balance_fen":1276050}`。

这条以前是假的（表里一行都没插过，永远返回空数组）。现在刷新页面能列出待确认卡片。**注意口径**：卡片行会列出，但 `future` 随进程消失，重启后的 `pending` 行不会再等任何人 —— 是「可列出、不可作答」。

## 五、评委若追问「被拒绝的痕迹在哪」

操作 F 这一轮的审计里**只有 `intent.parsed`**，没有 `policy.decided`、没有 `confirm.rejected` —— 因为拦截发生在意图层（模型连结构化意图都没编出来，`ok:false`），根本没走到裁决区。

这是已知限制，不是本轮新发现（`docs/红队失败归因.md` 的 O1 已登记：澄清轮不写裁决审计）。现场回答口径：**「这一句被拦在意图层，所以只有意图审计；要看裁决层留痕，请看重放里的黄灯与红灯两幕」**—— 不要声称系统对每次拦截都留了裁决记录。
