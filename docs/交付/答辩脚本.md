# 答辩脚本与现场清单（2026-10-27 版）

> 对着现在这个界面写的：四入口（AI 助手 / 账务 / 计划 / 治理）、助手页五块常驻裁决栏、确认卡三档动作。
> 全部截图与页面都出自 `banking-agent/web/`，本机 8000 端口。

## 一、开场 15 秒（背下来）

> “我们做的不是‘会转账的聊天机器人’，是**银行敢让它动钱的 Agent**。
> 今天不演示 AI 能不能转账，演示三件事：它凭什么被批准、凭什么被拒绝、出事之后凭什么查得清。”

## 四、三个必被问到的问题（标准答法）

1. **“为什么不用 LangGraph / 多 Agent 框架？”**
   “因为我们要的是**可审计的确定性**。图框架解决的是编排灵活性，我们这里的编排逻辑只有十几条分支，自己写状态机反而能把每一步写进审计；引入框架会让‘谁决定的’变得难追。真正承重的是策略引擎和令牌，不是编排器。”

2. **“模型被换了 / 被注入了怎么办？”**
   “两件事分开：模型只产出意图和计划，护栏在裁决区。我们现场把模型换成恶意 mock（`MOCK_MODE=true`，固定转出全部余额），意图判 unknown → 反问，零工具调用；就算它伪造调用，执行器没有能力令牌直接拒，拒绝还进审计。”

3. **“1000 元这条线怎么来的？”**
   “按赛题三色要求落成 R06/R07/R08：单笔越 1000 或日累计越 1000 都升红，红不是拒绝——强验证通过照样真实出账；只有绝对上限 R13 才是硬拦，且默认关闭。日累计按**用户**维度记，不是按账户，这样换卡也绕不过去。”

## 五、兜底预案（现场出事照这个做）

| 症状 | 处置 |
|---|---|
| 模型 API 不通 / 超时 | 演示前就设好 `MOCK_MODE=true` 跑一遍，确认脚本桩能演完整条；上台前再切回真模型，真模型一抖就切回去并说明“这是离线桩，逻辑一致” |
| 数据脏了（余额不对、有旧会话） | 治理 → 演示台 → **重置演示数据**（会收回智能体动过的钱、清会话；审计记录保留，这是设计如此） |
| 端口占用 | `make run` 前先 `lsof -i :8000`；换端口就改 `PORT`，令牌照旧 |
| Token 报错 / 页面空白 | 地址要带 `#token=...`（`app/main.py:115` 静态目录不校验，但接口要令牌）；不确定令牌就看启动日志第一屏 |
| 浏览器卡住 | 用 `make live-check` 现场自检一遍；再不行用备用机跑同一份仓库 |

## 七、三处必须主动承认的边界（写进第 13 页）

1. 理财只做适当性与申购/赎回，**没有持仓收益与横向对比**；
2. 订阅只做流水推断与取消，**没有推送通道**（本地提醒）；
3. 到点执行只提醒不代扣（资金动作永远要人点头）；
4. 语音与真实 IM 渠道未接（赛题非硬性）；
5. 沙箱按“**零执行面**”处理：`scripts/prove_no_exec_surface.py` 输出 15/15 自检通过，app/ 下不存在可被关进笼子的执行面。
