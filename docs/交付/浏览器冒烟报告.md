## 7. 查出来的缺陷与处理

### F-01（高）原脚本每次跑都污染答辩现场那份演示库

- **现象**：原脚本直接起仓库根的 uvicorn，`app/db.py:21` 的 `DEFAULT_DB_PATH = ROOT / "data" / "bank.db"` 落在仓库根；确认场景「转 100 元给妈妈」是真扣钱，于是**每跑一次冒烟，`data/bank.db` 的储蓄卡余额就少 100 元**，审计链也多一条。
- **实测证据**：改造前那次跑，`data/bank.db` 的 mtime 跟到跑的当分钟，且截图 03 的「交易后余额：1276050」就是写进演示库的那个数（12,760.50 = 12,860.50 − 100）。
- **处理**：脚本改为先把 `app/ web/ scripts/` 复制到 `tmp/browser_smoke_sandbox/` 再起后端 —— 后端的根目录落在沙箱里，`data/bank.db` 于是也落在沙箱里；种子在沙箱里重播一遍（`RANDOM_SEED=20261018`，余额回到 12,860.50 元，与 `docs/03` 校验表一致）。
- **反证（两层）**：
  1. **数据层**：转账落在沙箱库（余额 1276050、流水 `t_01133305 out 10000 妈妈 转账`），演示库仍是 1286050、末条流水还是种子那条 `t_00010025`。
  2. **逻辑层（脚本每次自动断言）**：`[不变量] 演示库 data/bank.db 余额 2685050 分未变，给妈妈的转账 0 笔（冒烟的钱没落进去）`。
- **保留的例外**：`--reuse`（复用手工起的服务）会改那个服务自己的库，脚本明说了，并跳过上面这条不变量断言。

### F-02（中）README 链的报告不存在

原 README 已经链到 `docs/交付/浏览器冒烟报告.md`，但那个文件当时**根本没建**（断链）。本文件即补上；另加回归用例 `test_report_link_not_rot` 挡住再次腐烂。

### F-03（低）PATH 上的 `playwright` CLI 包装器是坏的

`/home/peng/.local/bin/playwright` 的 shebang 指向的解释器里没装 playwright，`playwright --version` 直接抛 `ModuleNotFoundError`。
**不影响冒烟**（脚本用 Python API），但会误导人以为「playwright 没装」。此处记录，不改（属于环境问题，不是本仓代码）。

### F-04（中）共享工作区里，用文件指纹判断「我没污染」不可靠

- **现象**：某一轮冒烟报了 FAIL，同时 `data/bank.db` 变成 4096 字节 + 263KB `-wal`（像被 purge 后重播了种子）。
- **定位**：不是这次冒烟干的 —— 是**同机上队友并发跑的** `scripts/live_check.py` / `tmp/probe_t3_exp*.py` 在写同一个 `data/bank.db`（tmp/ 里 00:30-00:36 留下 live_*.db、probe_t3_exp*.py、chk_upsert.py 等）。逐步二分也验证了：`build_sandbox` 后演示库指纹不变、`seed_sandbox` 后不变，两次独立冒烟演示库字节完全不变。队友自己的 `scripts/live_check.py` 注释里就写着「跑完核对 data/bank.db 的 sha256 没变，变了就是污染」，但同一文件第 456 行又注明「sha256 仅作参考」—— **他们早就撞上同一个坑**。
- **处理**：不变量判据从「字节 sha256 未变」改成**逻辑判据**：冒烟后演示库**余额不变** 且 **「给妈妈的 100 元转账」笔数不增加** ⇒ 冒烟的钱没落进演示库。字节指纹只作提示（变了会说明「同机别的进程写的，不是冒烟干的」）。
- **恢复**：被并发脚本改坏的演示库已按种子原样恢复（`accounts` 余额 1286050 + 1399000 = 2685050、`transactions` 320 条、末条 `t_00010025` 山姆会员店、给妈妈的转账 0 笔），备份留在 `tmp/demo_bank_backup.db`。
- **附带改进**：端口被占用时不再直接失败，而是换一个空闲端口起自己的沙箱后端并打印说明（原来会 `SystemExit`，而同机联调脚本也占 8123，冒烟不该因此挂掉）。

### 一处**不是**缺陷的观察

聊天区气泡里的小标签 `n1` / `n2` / `done` 是 **SSE 事件名**（`web/index.html` 里 `appendBubble(role, text, tag)` 的第三个参数 `tag`），不是正文漏出来的协议串；把事件名打在气泡下方是刻意设计 —— 答辩时正好能看见「一个个事件流过来」。**不改**。
（聊天区里「交易后余额（后端原文）：1286050」显示的是分，标了「后端原文」也是刻意的透明化，不改。）

## 8. 残余风险登记册（接受，并说明为什么）

| # | 风险 | 为什么接受 |
| --- | --- | --- |
| R-01 | 只在 Chromium 桌面版（1440×960）验过；Firefox / Safari / 移动端没跑 | 前端是零依赖单文件，用的是 `fetch` + `ReadableStream` + `MutationObserver`；Safari 16.4 以下没有 ReadableStream，`web/index.html:556` 已有降级提示（「这个浏览器不支持流式响应，请换 Chrome 或 Edge 再试」）。答辩现场是本机 Chromium。 |
| R-02 | 「流式」只证明到 **2 个网络 chunk**（桩模式后端把 start+正文一起吐、done 单独一块），没证明「每个 token 一块」 | DOM 侧证据是硬的：4 批变更、文本长度 39→150 递增，说明**边收边渲染**成立。逐 token 的细粒度只有真实模型链路才有，MOCK_MODE=script 拿不出来。若答辩换真模型，需重跑本脚本。 |
| R-03 | 只断言 DOM 结构与关键文案，没做像素级视觉回归 | 截图是给人看的现场证据，不是回归基线；做视觉回归要引入基线图与容差维护成本，收益不匹配。 |
| R-04 | 确认卡的**「拒绝」分支**没点；确认过期（120 秒）与超时路径没在浏览器里验 | 这两条路径的后端逻辑另有 pytest 覆盖；浏览器层只验证了「主路径真的能点」。 |
| R-05 | **红灯（需多因子验证）**路径没在浏览器里验 | 需要构造一个触发 MFA 的场景，会牵到能力令牌签发与账户态，超出本次冒烟范围；绿灯、黄灯两条已在浏览器里验过。 |
| R-06 | 冒烟依赖本机有 Chromium | 缺失时脚本退出码 2 并打印明确原因，不静默跳过；安装命令已写进 README。 |
| R-07 | 演示库不变量只查「余额 + 给妈妈的转账笔数」两个维度 | 共享工作区里同机并发进程会改这个库（F-04），字节指纹不可用；这两个维度足以回答「冒烟那 100 元有没有落进演示库」这个唯一关心的问题。其余维度的改动一律不归因于冒烟。 |
