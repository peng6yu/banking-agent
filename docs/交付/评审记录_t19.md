## 1. 缺陷回顾（F1）

修复前的行为：今日已花 900 元，再预约 500 元 → `red / R11_default_deny / required_factors=[]`。

成因是三条规则之间的空隙，不是任何一条规则写错：
- R06 的条件含 `not _over_daily(...)` → 900+500 超过 1000，不匹配；
- R07 按设计豁免 `schedule_transfer`（`_DAILY_RULE_EXEMPT_TOOLS`，rules.py:40 / 判定 :315）→ 跳过；
- R08 只判单笔上限（500 ≤ 1000）→ 不匹配；
- 于是落到 R11 `default_deny`（when 恒真）→ 红且不带因子。

后果不是资金风险，而是**已知工具被兜底规则拒绝**：`executor._blocked` 对「红且无因子」直接终止，用户看到「这个操作我不确定是否安全，先不做」，审计记成 `DEFAULT_DENY`，事后归因会被误读成「模型调了未知工具」。钱次日才出账，创建当日本不该受日线约束。

## 2. 修复内容核对

`app/policy/rules.py:304-306` 现为：

```python
lambda action, ctx: _is_spend(action)
and 0 < _amount(action) <= ctx.single_limit_fen
and (action.tool in _DAILY_RULE_EXEMPT_TOOLS or not _over_daily(action, ctx)),
```

核对结论：改的是**日线这半个条件**，单笔上限条件与 R08 一字未动。注释写明了为什么改、以及「豁免的只是日线，单笔上限仍由上面的条件与 R08 管」——把理由留在代码里，下一个人不会把它当 bug 删掉。

## 4. 安全性追问：豁免后日线靠什么守
