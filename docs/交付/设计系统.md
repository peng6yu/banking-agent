# 设计系统（2026-10 重构）

> 为什么先定规范再改页面：这个项目上一版的毛病不是"不好看"，而是**同一件事在不同地方长得不一样**——
> 三种绿色、两种"已成功"、金额有的带千分位有的不带、异常有时叫"风险"有时叫"可疑"。
> 所以这一轮先在 `web/index.html` 顶部把变量层钉死，再让六区所有页面只引用变量。

代码位置：`web/index.html` 第 12–84 行（变量层），其后是基础排版与组件样式。
前端仍然是**单文件**：仓库自带的 `scripts/check_frontend.py` 禁止外部资源（`<link>`、`<script src>`、`@import`、CSS `url()`、`EventSource`），
离线演示也要求双击就能开。改造时没有引入任何前端框架——收益（组件化）远小于代价（构建链、离线包、回归面）。

## 三、状态与文案的统一口径

- **任务九态**（`app/api/business.py:TASK_STATE_LABELS`）：草稿 / 等待补充信息 / 等待确认 / 等待验证 / 执行中 / 已成功 / 已失败 / 已取消 / 需要人工处理。前端不再自己编词。
- **计划五态**（`plans_view.state_legend`）：计划已保存 → 任务已安排 → 任务正在执行 → 任务已完成 → 已失败/已取消。**只有后端持久化且状态为 `scheduled` 的才允许显示"已安排"**。
- **异常只有一档**："发现异常（待核实）"。任何页面都不出现"欺诈""违规"这类定性词（`tests/test_business_api.py` 有断言）。
- **订阅**：一律"已停掉银行侧代扣（商户会员本身没有取消）"。
- **冲正**：一律"账务冲正（本地反向记账），不代表能从对方追回"。
- **手续费**：拿不到可信数据时显示"本演示环境不计算手续费；真实资费以银行公示为准"，不写 0，也不猜数字。

## 四、交互规范

1. **技术细节默认折叠。** 意图、DAG、策略裁决、令牌、审计放在"执行详情"里按需展开；普通用户第一屏只看到业务状态、风险说明、下一步操作。
2. **确认不等于成功。** 点确认后按钮进入等待态，最终状态只认后端返回与审计链；刷新页面走 `bxRestoreSession` 重新拉 `/api/session`。
3. **改选收款人必须换确认号。** 选择器只回填 `尾号####`，前端不改任何计划状态——计划由后端重新生成（截图里两个"张三"，确认号从 cf_… 变化可证）。
4. **空状态写原因，不写"暂无数据"。** 例："还没有预约任务" / "没有任何需要你确认的操作"。
5. **禁用态**：不可点按钮 `disabled` + 文案说明为什么不可点（如"已过期"），不静默变灰。

## 五、已知取舍

- 没有暗色主题：比赛现场是投屏 + 手机同屏，浅色在两种设备上都稳；暗色要多维护一套对比度，收益不明显。
- 没有引入组件框架（React/Vue）：见文首理由。
- 图标用文字与内联 SVG 少量使用，不引图标库（离线要求）。
- 响应式只有两档断点（≥1024 两栏、<768 单栏），够手机看，不做平板专属布局。
