### 2.1 查余额（balance）

- 原话：我工资卡现在还有多少钱？
- 解析：`intent=query_balance`，`confidence=0.9`，缺槽位无，反问无，模型未填任何槽位
- 策略：`n1 query_balance` → **green** / `R01_readonly`（只读，不进确认）
- 工具：`query_balance` ok=true → 「余额 12,860.50 元」
- 动钱：否（余额 2685050 → 2685050 分，流水 320 → 320）
- 模型请求：1 次，1387ms，`finish_reason=tool_calls`，工具 `emit_intent`
- 失败原因：无

### 2.2 分析账单（bill）

- 原话：帮我看看上个月的账单，有没有什么异常消费？
- 解析：`intent=bill_analysis`，`confidence=0.95`，缺槽位无，反问无，**模型未填 `month`**（本次 `slots={}`）
- 策略：`n1 analyze_bill` → **green** / `R01_readonly`
- 工具：`analyze_bill` ok=true → 「账单支出合计 17,462.00 元」
  （17,462.00 元 = 库里 2026-09 的支出合计；今天 2026-10-23，「上个月」= 2026-09，**这一次月份是对的**）
- 动钱：否
- 模型请求：1 次，3049ms
- 失败原因：无

### 2.3 申购基金（fund）

## 3. 本次实跑暴露的真实问题（交队长定夺）

### 3.1 「上个月的账单」同一句话跑出三种结果，其中一次**月份差了一个月**

同一句「帮我看看上个月的账单，有没有什么异常消费？」在 2026-10-23 跑了 7 次（今天 10-23，「上个月」= 2026-09）：

| 次 | 结果文件 | 模型槽位 | 模型自报 missing | 分析到的月份 | 金额 |
| --- | --- | --- | --- | --- | --- |
| 1 | `tmp/live_run_bill_fund.json` | 未采集 | `['month']` | —— | 反问「要看哪个月？」 |
| 2 | `tmp/live_run_bill2.json` | 未采集 | 无 | 2026-09 ✓ | 17,462.00 元 |
| 3 | `tmp/live_run_all.json` | 未采集 | 无 | **2026-08 ✗** | **18,583.00 元** |
| 4 | `tmp/live_bill_rep1.json` | `{"period":"month"}` | 无 | 2026-09 ✓ | 17,462.00 元 |
| 5 | `tmp/live_bill_rep2.json` | `{"period":"month"}` | `['month']` | —— | 反问「要看哪个月？」 |
| 6 | `tmp/live_bill_rep3.json` | `{"period":"month"}` | 无 | 2026-09 ✓ | 17,462.00 元 |
| 7 | `tmp/live_run_final.json` | `{}` | 无 | 2026-09 ✓ | 17,462.00 元 |

（库里主账户尾号 1234 的月度支出合计：2026-07 = 12,705.00、2026-08 = **18,583.00**、2026-09 = **17,462.00**、2026-10 = 7,327.00 元，
第 3 次的金额与 8 月完全一致、且不等于默认窗口的 9 月，因此只能是模型填了 `month=8`；该次未采集槽位，属推断。）

三种行为对应的机制（代码事实，非猜测）：

1. **模型自报 `missing:["month"]` → 反问**。
   `app/planner/intent.py:367-380` 的 `_missing()` 会把模型自报的 missing 归一后当缺槽位处理，
   模型说缺 month，系统就反问「要看哪个月？」——**哪怕用户说的是「上个月」这种完全确定的相对时间**。
2. **模型不填 month 也不报缺 → 用系统默认窗口**。
   `app/planner/dag.py:352-359` 的 `_bill_params()`：`year/month` 默认取 `_previous_month(clock.now_ms())`，
   即上一个自然月（2026-09），这一路是对的。
3. **模型填了 `month` → 直接覆盖系统默认**。
   同上：`"month": _positive_int(slots.get("month")) or month` —— 模型填 8 就分析 8 月，**系统不校验、不提示**。

配套的两个小问题：

- `app/planner/intent_schema.py:184` 里 `month` 只有 `{"type": "integer"}`，**没有 SLOT_GUIDE 说明**告诉模型该写什么
  （`SLOT_GUIDE` 的键只有 card_tail/merchant/action/purpose/gift/date_hint/due_hint/recurrence/payee_names/txn_ref/payee_phone，
  **不含 month**），所以模型要么不填、要么填错。
- `app/planner/intent.py:319-323` 对 `month` 走 `_int_or_none`，模型给 `"2026-09"`、`"9月"` 这类写法会被**直接丢弃**。
- 用户看到的账单摘要由 `app/planner/events.py:40` 生成，只有一句「账单支出合计 N 元」，
  **不带月份标签**（工具结果里其实有 `range.label`，例如「2026年8月」）。所以用户无法核对分析的是哪个月 ——
  第 3 次那种「差一个月」的结果，用户没有任何线索能发现。

**这是本次实跑里最值得处理的一条**：不是偶发成功，是**可复现的偶发失败**（7 次里 2 次反问、1 次月份错）。

### 3.2 亲属称谓「我妈」没有落到 `payee_name`

真模型解析 `birthday_plan` 时填了金额、礼物、用途，**没有把「我妈」映射成收款人名字**，
于是缺 `payee_name` 被反问。**从安全角度这是对的**（绝不猜收款人就去锁资金、付商户），
但赛题句式「我妈生日送礼」在真模型下就是走不通 —— 需要产品决定：亲属称谓是否应触发
「请从通讯录选人」的引导，或者由规划层把亲属称谓显式归一化成候选收款人。

### 3.3 红灯场景的因子要求（属预期，不是缺陷，但请队长确认赛题口径）

- 申购基金（`R10_invest_red`）要 `face+otp`；
- 冻结卡（`R09_sensitive_red`）要 `face+sms+otp`。

真模型下这两个场景的**双因子链路本身是通的**（factor 卡正常升起、按 required 补齐后放行、工具执行成功），
本次是脚本按现场用户做法补齐因子后跑通的。若赛题要求「一句话无人工介入即完成」，
这两条红灯规则需要队长确认是否要在赛题口径下另开特例。

### 3.4 冻结卡场景模型编了个多余金额（低危）

模型给「冻结尾号 1234 的卡」填了 `amount_fen=123400`（1234.00 元，看起来是把卡号当成了金额）。
本次没有造成任何后果（冻结卡工具不吃金额参数，余额与流水都没动），但它说明**模型会往槽位里塞用户没说的数**，
一旦某个工具的同名槽位被误用，就会变成真金白银的偏差。留档在这里，供队长判断是否要加槽位白名单/校验。

## 4. 复现步骤

前置：`.env` 里配好 `MINIMAX_API_KEY` 与 `MINIMAX_API_HOST`（脚本不打印密钥）。

```bash
cd banking-agent
export PATH=$PATH:/home/peng/.local/bin && export PYTHONPATH=.

# 离线自检（默认不连网，只验链路与库隔离）
python3.12 -m scripts.live_check

# 真模型六场景（串行，场景间 sleep 1s）
python3.12 -m scripts.live_check --live --json tmp/live_run_all.json

# 只跑某几个场景
python3.12 -m scripts.live_check --live --only bill --only fund
```

退出码：`data/bank.db` 被打开过，或任一场景有失败项 → 1。

每次运行的完整逐次模型请求（模型名、单次耗时、工具调用、`finish_reason`）、429 退避记录、
**模型填的槽位**、库打开路径清单、场景前后余额/流水快照，都写进 `--json` 指定的文件。

## 5. 离线模式（默认）说明

`python3.12 -m scripts.live_check`（不加 `--live`）不连网，用 `app/llm/ScriptAdapter` 回放：

- 它只认「余额 / 转账」两类说法，**其余场景会走 `unknown` 反问**「你是想查询、转账还是看账单？」——
  这是如实行为，不是脚本坏了；
- 离线模式只验证「链路通、库隔离成立」，**不校验模型理解能力**，模型能力以本文档的 `--live` 结果为准；
- 离线模式下 6 个场景同样 0 次命中 `data/bank.db`。
