## 2. 逐场景明细

### 2.1 查余额（balance）

- 原话：我工资卡现在还有多少钱？
- 解析：`intent=query_balance`，`confidence=0.93`，缺槽位无，反问无
- 策略：`n1 query_balance` → **green** / `R01_readonly`（只读，不进确认）
- 工具：`query_balance` ok=true → 「余额 12,860.50 元」
- 动钱：否（余额 2685050 → 2685050 分，流水 320 → 320）
- 模型请求：1 次，6076ms，`finish_reason=tool_calls`，工具 `emit_intent`
- 失败原因：无

### 2.2 分析账单（bill）

- 原话：帮我看看上个月的账单，有没有什么异常消费？
- 解析（**成功那次**）：`intent=bill_analysis`，`confidence=0.92`，缺槽位无
- 策略：`n1 analyze_bill` → **green** / `R01_readonly`
- 工具：`analyze_bill` ok=true → 「账单支出合计 17,462.00 元」
- 动钱：否
- 模型请求：1 次，5105ms
- 失败原因：无
- **同句首跑**：模型没填 `month` 槽位 → 触发反问「要看哪个月？」，详见 §3.1

### 2.3 申购基金（fund）

- 原话：帮我申购 1000 元的均衡配置混合A
- 解析：`intent=invest`，`confidence=0.95`
- 策略：`n1 buy_fund` → **red** / `R10_invest_red`
- 确认：factor 卡 `required=['face','otp']`，脚本按现场做法补齐双因子 → `approved`
- 工具：`buy_fund` ok=true → 「buy_fund 执行完成」
- 动钱：**是**，余额 2685050 → 2585050 分（−1000.00 元），流水 320 → 321
- 模型请求：1 次，2027ms
- 失败原因：无

### 2.4 冻结卡（freeze）

- 原话：帮我把尾号 1234 的银行卡冻结掉
- 解析：`intent=card_manage`，`confidence=0.95`
- 策略：`n1 freeze_card` → **red** / `R09_sensitive_red`
- 确认：factor 卡 `required=['face','sms','otp']`，补齐后 `approved`
- 工具：`freeze_card` ok=true → 「尾号 1234 的卡已冻结，现在不能再用它付款。」
- 动钱：否（冻结不产生流水）
- 模型请求：1 次，1570ms
- 失败原因：无

### 2.5 取消订阅（subscription）

- 原话：帮我把爱奇艺会员的自动续费取消掉
- 解析：`intent=subscription`，`confidence=0.95`，订阅名正确落到爱奇艺会员
- 策略：`n1 list_subs` → green / `R01_readonly`；`n2 cancel_subscription` → **yellow** / `R05_confirm_only`
- 确认：confirm 卡 `required=[]`（黄灯只需点头），`approved`
- 工具：`list_subs` ok=true → 「在订订阅 5 项，每月 251.00 元」；`cancel_subscription` ok=true → 「已取消订阅「sb_00000001」」
- 动钱：否（取消订阅不扣款、不产生流水）
- 模型请求：1 次，1145ms
- 失败原因：无

### 2.6 我妈生日送礼（birthday）

- 原话：我妈下周生日，帮我订一束花送给她，预算 300 元
- 解析：`intent=birthday_plan`，`confidence=0.93`，**缺槽位 `['payee_name']`**
- 策略：未进策略层（缺必填槽位就反问，不会带着半截参数去锁资金/付商户）
- 确认：无
- 工具：无
- 动钱：否
- 模型请求：1 次，2967ms
- 失败原因：无（这是**如实的产品行为**，不是报错）：反问「这份礼物是给谁过生日？」，见 §3.2

## 3. 本次实跑暴露的真实问题（交队长定夺）

### 3.1 「上个月」的账单槽位会抖：同一句话两次跑，结果不同

- 第 1 次（`tmp/live_run_bill_fund.json`）：`missing=['month']` → 反问「要看哪个月？」，3281ms，没进策略层。
- 第 2 次（`tmp/live_run_bill2.json`）：`missing=[]` → 跑通，「账单支出合计 17,462.00 元」，5152ms。

机制（代码事实，非猜测）：

- `app/planner/intent_schema.py:184` 里 `month` 只声明成 `{"type": "integer"}`，**没有 SLOT_GUIDE 说明**告诉模型该怎么写
  （`period`/`month` 只出现在 `SLOT_KEYS` 列表里，不在 `SLOT_GUIDE` 描述表里）；
- `app/planner/intent.py:319-323` 对 `month` 走 `_int_or_none`（`app/planner/intent.py:426-434`），
  模型给出非整数（`"2026-09"`、`"9月"`、空串）就**直接丢弃**该槽位；
- `app/tools/bill.py:45-50` `analyze_bill` 必须要 `params["year"]` 与 `params["month"]`，
  缺 month 时抛 `ValidationError("按月分析要告诉我几月")`。

也就是说：**相对时间词「上个月」→ 槽位 `month` 的取值格式没有契约**，模型只能猜，猜错就丢槽位并反问。
这是可复现的偶发失败，不是偶发成功。

### 3.2 亲属称谓「我妈」没有落到 `payee_name`

真模型解析 `birthday_plan` 时只填了 `purpose/gift/date_hint/amount_fen` 一类槽位，没有把「我妈」映射成收款人名字，
于是缺 `payee_name` 被反问。**从安全角度这是对的**（绝不猜收款人就去锁资金付商户），
但赛题句式「我妈生日送礼」在真模型下就是走不通 —— 需要产品决定：亲属称谓是否应触发「请从通讯录选人」的引导，
或者由规划层把亲属称谓显式归一化成候选收款人。

### 3.3 红灯场景的因子要求（属预期，不是缺陷，但请队长确认赛题口径）

- 申购基金（`R10_invest_red`）要 `face+otp`；
- 冻结卡（`R09_sensitive_red`）要 `face+sms+otp`。

真模型下这两个场景的**双因子链路本身是通的**（factor 卡正常升起、按 required 补齐后放行、工具执行成功），
本次是脚本按现场用户做法补齐因子后跑通的。若赛题要求「一句话无人工介入即完成」，
这两条红灯规则需要队长确认是否要在赛题口径下另开特例。

## 4. 复现步骤

前置：`.env` 里配好 `MINIMAX_API_KEY` 与 `MINIMAX_API_HOST`（脚本不打印密钥）。

```bash
cd banking-agent
export PATH=$PATH:/home/peng/.local/bin && export PYTHONPATH=.

# 离线自检（默认不连网，只验链路与库隔离）
python3.12 -m scripts.live_check

# 真模型六场景（串行，场景间 sleep 1s）
python3.12 -m scripts.live_check --live --json tmp/live_run_all.json

# 只跑某几个场景
python3.12 -m scripts.live_check --live --only bill --only fund
```

退出码：`data/bank.db` 被打开过，或任一场景有失败项 → 1。

每次运行的完整逐次模型请求（模型名、单次耗时、工具调用、`finish_reason`）、429 退避记录、
库打开路径清单、场景前后余额/流水快照，都写进 `--json` 指定的文件。

## 5. 离线模式（默认）说明

`python3.12 -m scripts.live_check`（不加 `--live`）不连网，用 `app/llm.ScriptAdapter` 回放：

- 它只认「余额 / 转账」两类说法，**其余场景会走 `unknown` 反问**「你是想查询、转账还是看账单？」——
  这是如实行为，不是脚本坏了；
- 离线模式只验证「链路通、库隔离成立」，**不校验模型理解能力**，模型能力以本文档的 `--live` 结果为准；
- 离线模式下 6 个场景同样 0 次命中 `data/bank.db`。
