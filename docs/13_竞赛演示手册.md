# 13 竞赛演示手册（三段演示 · 可复现）

> 对应任务书阶段 7.2。三段演示都在**同一份代码**上跑，命令可直接复制执行。
> 文中所有「预期」都来自 2026-10-24 的实测，不是设计推演；未实测的部分明确标注。
> 前置：`cd banking-agent`，已完成 `make setup`（或系统 python3.12 装好 `requirements.txt`）。

## 0. 启动（每段演示共用）

```bash
cd banking-agent
.venv/bin/python -m scripts.seed        # 初始化/重置演示库（虚构数据）
.venv/bin/python -m uvicorn app.main:app --port 8000
```

启动日志会打印 `http://127.0.0.1:8000/#token=…`，其中：

- **浏览器演示**：直接打开这条地址，令牌存进 sessionStorage，之后同标签页可直接刷新；
- **命令行演示**：把令牌放进 header，两种都认（`app/api/routes.py:239`）：

```bash
export TOK="$(cat data/api_token)"     # 或启动日志里 token= 后面那串
curl -s -H "X-API-Token: $TOK" http://127.0.0.1:8000/api/health
```

预期 `/api/health` 返回 `status=ok`、`tools=35`、`db=true`。
`tools=35` = 原有 26 个 + 主动财务管理 7 个 + 适当性 2 个（只读 13 / 写 22）。

> 演示全程使用**本地虚构数据**（`scripts/seed.py` 生成的用户/账户/流水）。
> 不连接任何真实银行、不发起真实转账。`simulate` 接口写入的流水固定 `simulated=true`。

## 演示 A：自然语言办理银行业务（含歧义与权限）

**结论先行**：一句话 → 意图/槽位 → DAG → 三色权限 → 确认/双因子 → 受限执行 → 审计，
每一步都能在界面上看到，且「模型说的」和「代码定的」是分开的。

### A-1 歧义必须先问（知识层的确定性护栏）

浏览器输入：

> 转500给王

预期（实测）：系统不建图，而是反问
「「王」是哪一位收款人？请给全名，或补上卡号后四位，我才好确认。」
对应测试：`tests/test_knowledge_integration.py::test_bare_surname_payee_asks_which_person`。

再试一句两笔：

> 转500给张三，也转500给李四

预期：要求一次说一笔（`MULTI_PAYEE_QUESTION`），不会只转第一笔、把第二笔静默丢掉。

### A-2 正常转账：确认 + 执行 + 审计

输入（收款人「张三」在种子里有两条：尾号 4417 工行 / 6620 中行）：

> 转500给张三

预期 SSE 依次出现：

1. `intent`：`intent=transfer`、`slots` 含 `payee_name=张三`、`amount_fen=50000`；
2. 若模型只给了名字，`resolve_payee` 节点返回两个候选 → 系统追问「尾号后四位 / 第几个」；
   回答 `4417` 后续跑；
3. 计划面板出现 3 个节点：`resolve_payee → query_balance → transfer`，串行依赖；
4. 权限灯：500 元在单笔/日累计 1000 元以内 → **黄灯**，弹出确认卡片；
5. 点「确认」→ 节点依次 done，余额减少 500 元，账户余额与流水同步；
6. 审计面板新增记录，`GET /api/audit/verify` 返回链完整。

### A-3 权限升级：超过分界就要双因子

输入：

> 转2000给张三

预期：**红灯** `R08_transfer_red_single`（或日累计 `R07`），
确认卡片要求 `face` + `sms`。命令行演示确认：

```bash
# 缺因子 → 拒绝放行
curl -s -X POST -H "X-API-Token: $TOK" -H 'Content-Type: application/json' \
  -d '{"session_id":"'$SID'","confirmation_id":"'$CID'","approve":true}' \
  http://127.0.0.1:8000/api/confirm
# 预期：ok=false / 状态仍 waiting_factor / 原因写明缺哪个因子

# 双因子齐全 → 放行（"face,sms" 也可以是 "face+sms"）
curl -s -X POST -H "X-API-Token: $TOK" -H 'Content-Type: application/json' \
  -d "{\"session_id\":\"$SID\",\"confirmation_id\":\"$CID\",\"approve\":true,\"factor\":\"face,sms\"}" \
  http://127.0.0.1:8000/api/confirm
```

> 因子名取自 `app/policy/rules.py`：转账红 = `face,sms`，理财红 = `face,otp`，
> 解析见 `app/planner/state.py::factors_ok`（`face+sms`、`sms,face` 都认）。
> `$SID`（session_id）从 `/api/chat` 的 SSE `intent` 事件里取，`$CID` 从确认事件里取。

**要讲清的一句话**：模型输出只是「操作申请」，红灯放不放行由 `app/policy/engine.py` 决定，
确认令牌与参数绑定，改金额会重新裁决。

## 演示 B：AIR 对标与领域知识增强（A/B 对照）

**结论先行**：知识层不进模型上下文，只在确定性层影响三件事——**问不问、填什么、怎么解释**，
并且在审计里留下 `knowledge.retrieved` 事件，可回指到具体知识条目与来源。

### B-1 术语规范化 + 跨场景规划

输入：

> 把F00001赎回来转3000给我妈

预期（实测 `tests/test_knowledge_integration.py::test_colloquial_redeem_with_product_code_builds_cross_plan`）：

- 识别为跨场景 `redeem_then_transfer`；
- 产品代码由确定性规则从原话补进槽位（`F00001`），不反问用户刚说过的值；
- 建出 **4 节点串行图**：`resolve_payee → redeem_fund → query_balance → transfer`，
  顺序是业务含义：先把收款人问清（只读、早失败），再受理赎回，再看可用余额，最后转账；
- 两个红灯各有各的因子：`redeem_fund` 要 `face,otp`，`transfer` 要 `face,sms`；
- 审计写入 `knowledge.retrieved`，payload 含 `knowledge_ids`、`sources`、`version`、`cross`。

再说一句口语版（不说产品代码）：

> 把货币基金卖了转3000给我妈

预期：判出跨场景但**不建图**，反问「赎回要先知道是哪只产品：请说产品代码或产品名……」。
这正是「知识不足就追问，不猜」的现场证据。

### B-2 权威来源怎么念

知识层把来源分成三档（`rule_level`）：`law` / `bank_public` / `contest_simulation`。
回答里说「法规要求」「某家银行的公开规则是」「本原型设定为」是三种不同话术，
未核实的来源会明确标注（`app/planner/kb_bridge.py::explain`）。
知识来源登记见 `knowledge/sources.yaml`（34 条）与 `docs/银行业务知识来源清单.md`。

### B-3 A/B 对照怎么跑（可复现）

```bash
cd banking-agent
# A 组：关闭知识层（KNOWLEDGE_ENABLED=0）
.venv/bin/python -m tests.eval.run_eval --cases tests/eval/intent_cases.yaml \
  --out tests/eval/results --group a --concurrency 2
# B 组：知识层开（删除该环境变量）
.venv/bin/python -m tests.eval.run_eval --cases tests/eval/intent_cases.yaml \
  --out tests/eval/results --group b --concurrency 2
```

产物：`tests/eval/results/<时间戳>/{cases_a,cases_b}.jsonl, summary.json, report.md`。
指标：意图准确率、关键参数准确率、歧义澄清准确率、DAG 合法率、
知识引用正确率、未授权写操作（规划级）计数。
**真实数字写在 `tests/eval/evaluation_report.md`，现场只念那份报告里的数，不要临场估算。**

## 演示 C：主动财务管理（储蓄目标 → 计划 → 监测 → 提醒 → 调整）

**结论先行**：金额由确定性代码算（`int` 分，无浮点），模型只负责组织人话；
主动财务**没有任何动钱工具**，也不能绕过原有授权自动转账或申购。

### C-1 建目标（浏览器或 curl 皆可）

界面上「主动财务」面板填：名称「换手机」、目标 5000 元、目标日期 `2026-12-31`、已存 0 元。

等价命令：

```bash
curl -s -X POST -H "X-API-Token: $TOK" -H 'Content-Type: application/json' \
  -d '{"name":"换手机","target_fen":500000,"target_date":"2026-12-31","saved_fen":0}' \
  http://127.0.0.1:8000/api/savings/goals
```

预期（实测）：返回 `goal_id`、`remaining`、`periods_remaining=3`、
`required_per_period`、`feasibility`、`plan`（含 assumptions 口径说明）。
注意返回键是 `goal_id`（不是 `id`）。

### C-2 看计划与计算依据

页面「计划」区展示：当前累计、距目标差额、剩余周期数、每期要求、历史平均收入、
固定支出、必要可变支出、预计结余、可行性结论。
公式与口径（`docs/12_主动财务管理设计.md`）：

```
剩余目标 = 目标金额 − 当前可计入储蓄
阶段性要求 = 剩余目标 ÷ 剩余周期数（向上取整到分）
预计周期结余 = 周期收入 − 固定支出 − 必要可变支出
```

可行性为 `infeasible` 时，页面会说明原因并给调整方案，不会硬凑一个「看起来合理」的储蓄额。

### C-3 注入一笔模拟支出 → 跑监测 → 触发提醒

```bash
curl -s -X POST -H "X-API-Token: $TOK" -H 'Content-Type: application/json' \
  -d '{"amount_fen":12000,"merchant":"便利店","category":"购物","note":"演示注入"}' \
  http://127.0.0.1:8000/api/proactive/simulate/expense

curl -s -X POST -H "X-API-Token: $TOK" -H 'Content-Type: application/json' \
  -d '{}' http://127.0.0.1:8000/api/proactive/monitor/run
```

预期（实测）：`simulate` 返回 `transaction`、`balance_after_fen`、`simulated=true`
与提示「这是竞赛演示用的模拟流水，不对应任何真实支付。」；
`monitor/run` 返回 `status=ok`、`alerts_created=1`，alert 带 `evidence`
（如 `avg_income_fen`、`period_gap_fen`、`dedupe_key`）和一句人话建议。

**必须现场说明**：这是**手动触发**的一次监测（`POST /api/proactive/monitor/run`），
没有 7×24 后台定时器；界面文案也这么写。不要把它说成「全天候管家」。

### C-4 处理提醒 → 调整目标 → 重算

```bash
curl -s -X POST -H "X-API-Token: $TOK" -H 'Content-Type: application/json' \
  -d '{"action":"ignore"}' http://127.0.0.1:8000/api/proactive/alerts/<ALERT_ID>/resolve

curl -s -X PATCH -H "X-API-Token: $TOK" -H 'Content-Type: application/json' \
  -d '{"target_fen":4000000}' http://127.0.0.1:8000/api/savings/goals/<GOAL_ID>
```

预期（实测）：忽略后同周期不再生成同类提醒（`alerts_created=0`）；
改目标后 `required_per_period` 按新目标重算（示例：目标 40000 元 → 13,333.34 元/期）。

### C-5 交互闭环（浏览器）

建目标 → 列表出现 → 点「跑一次监测」→ 提醒列表出现 → 点「忽略」/「已解决」→
改目标 → 再次监测并看到新的计划。前端所有后端值走 `escapeHtml`，
模拟支出接口不可用时会显示「后端接口未就绪」，不会假装成功。
