## 1. Revolut AIR 研究得出的产品与工程启示

研究入口（均实际打开，证据状态逐条标注在 `docs/benchmark/revolut_air_research.md`）：

- 产品页：https://www.revolut.com/air-ai-by-revolut/
- 发布公告：https://www.revolut.com/news/revolut_enters_new_era_of_money_intelligence_with_launch_of_ai_assistant/
- 官方博客：https://www.revolut.com/blog/post/air-ai-by-revolut/

### 1.1 官方证实的

1. AIR 的定位是「用自然语言问钱的事」：查消费、看收支、找订阅、理解某笔支出，交互是**对话式**而不是菜单式。
2. 它的强项是**把用户自己的流水翻译成人能看懂的解释**，而不是替用户下单。
3. 官方明确强调安全与隐私（包括零数据留存的相关表述），并把「AI 给建议、人做决定」作为边界。
4. 官方公开材料以产品能力与用户价值为主，**没有公开**内部模型、编排框架、工具调用链、知识库实现。

### 1.2 合理推断（明确标为推断）

- 要支撑「问一句就能答」，AIR 内部必然有意图理解 + 数据检索 + 回复组织三段，但**具体是单 Agent 还是多 Agent、是否用 RAG、用什么模型，官方没有证据**，本项目不作断言。
- AIR 的产品形态以**响应式**为主：用户问，它答。公开材料里**没有找到**「主动推送储蓄计划/主动预警」的官方证据，因此本项目没有把「AIR 有主动服务」当作事实。

### 1.3 对本项目的三条启示

| 启示 | 落到本项目 |
|---|---|
| 用户价值在「解释」而不只在「执行」 | 主动财务管理做的是计划、依据、偏差解释；资金操作仍走原授权链 |
| 安全边界必须产品化表达 | 三色权限灯、确认卡、双因子、审计链本来就是强项，改造中**一条都没有放松** |
| 不要为了对标而堆基础设施 | 知识层用结构化 YAML + 确定性检索，不引入向量库/图数据库；没有证据的能力不做 |

## 3. 新增知识层如何接入并改善业务理解

### 3.1 接入点（不是提示词堆料）

```text
用户消息
  → 术语规范化（app/knowledge/normalize.py，字面别名，确定性）
  → 检索（retrieve：意图规则 + 术语 + 流程 + 来源，结构化匹配）
  → kb_bridge.advise() 产出 Hint
  → LLM 意图/槽位（原有链路，messages 结构未动）
  → Hint 修正：纠意图 / 补槽位 / 追加必填 / 置跨场景标记
  → DAG 模板（dag.py，跨场景用 CROSS_TEMPLATES）
  → app/policy 确定性裁决（知识层不可达）
  → 确认 / 强验证 / 令牌 / 执行 / 审计
```

四个实际调用点：

1. `app/planner/intent.py:parse()` → `_from_args` 之后应用 `slot_patches`、`extra_required`、`hint.ask`、意图纠正；
2. `app/planner/dag.py:build_or_single(intent, cross=...)` → 跨场景串行图；
3. `app/api/routes.py:_audit_knowledge()` → 每轮写 `knowledge.retrieved`（ids/sources/version/degraded/cross）；
4. 回答层 `explain()` → 只念已核实来源，未核实显式标注。

**边界**：知识只影响「问不问 / 填什么 / 怎么解释」，不影响「放不放行」。`SYSTEM_PROMPT` 与 messages 结构被测试逐字钉死，所以知识**不进模型上下文**——避免截断、避免模型拿知识当放松校验的理由。

### 3.2 行为上的真实改变（有 case）

- **跨场景**：C048「先赎回再转5000给张三」——A 组直接建转账图；B 组识别 `redeem_then_transfer`，先问「哪只产品（F00001 现金添利货币A）」，补齐后才建 4 节点图。
- **缺金额**：C030「把理财赎回来」——B 组追问金额或「全部赎回」，不猜。
- **同义/口语**：「转500块」「预约转账」等规范化后进入对应意图；「预约转账」被模型误判为即时转账且无 `due_ms` 时，纠正为 `schedule_transfer`。
- **失败降级**：知识加载/检索异常、来源未核实 → `Hint(degraded=True)`，退回原有规则并留审计，不会放开权限。

### 3.3 A/B 实验（同轮、同模型、同 80 例）

最终轮（`20261023T210056`，并发 1）：intent **+5.0pp**（67→71/80）、slot **+5.48pp**（60→64/73）、clarify **−2.5pp**（71→69/80）、DAG 1.0、未授权「未追问即列写工具」**4→0**。

归因必须分开：`payment_guard` 在 A/B 都生效，消掉 C039/C044（多收款人/一句两笔）；知识层消掉 A 组剩余的 C029/C030/C037/C042（多候选/裸姓、赎回缺金额、关系称谓、缺槽位）。clarify 的 −2.5pp 来自 C006/C007/C021/C053 代扣解约退化与 C024/C047 多问，报告不宣称知识层稳定提升追问率。

知识引用 42/51 是术语 id 字面一致率；49 条有期望知识的 case **全部**拿到意图规则与工作流（49/49），只有 40/49 拿到字面术语 id。dev（60）与 holdout（20）分层结果见评估报告 §4.2。

> **时差声明**：上述 A/B 轮跑完后，第二轮审查又改了 guard 否定分句、模型 missing 白名单、代扣解约原话信号；模型配额在 22:10 耗尽（429），无法重跑。最终提交的说法是「最后一轮有效 A/B + 后续改动的测试证据」，不是「最终代码的 A/B 轮」。

## 4. 主动财务管理的完整实现情况

### 4.1 闭环（真实跑通）

```text
创建目标（3 万 / 2026-12-31 / 每月）
→ 读 320 笔模拟流水，算收入、固定支出、必要可变支出、可用结余
→ 确定性计算：剩余目标、每期应存、可行性、预算偏差（int 分，Decimal 语义）
→ 生成带假设与依据的计划（模型只解释，不算金额）
→ 建储蓄目标 + 监测规则
→ 注入一笔模拟支出 → 手动跑监测
→ 进度回写、偏差判定、创建带证据的提醒（同日去重）
→ 用户忽略/处理提醒
→ 修改目标 → 重算并展示新计划
```

### 4.2 代码与数据

- `app/proactive.py`：确定性计算 + 仓储 + `run_monitor()`（两段事务，失败也留 `monitor_runs` 记录）；
- 表：`savings_goals` / `monitor_rules` / `proactive_alerts` / `monitor_runs`（18→22 张）；
- 工具 7 个：`list_savings_goals`、`compute_savings_plan`、`create_savings_goal`、`update_savings_goal`、`list_proactive_alerts`、`resolve_proactive_alert`、`run_proactive_monitor`（无任何动钱工具）；
- API 6 个 + `POST /api/proactive/simulate/expense`（只写模拟流水，禁透支，同日幂等）；
- 前端：目标表单、进度、计划与依据、偏差、提醒列表、处理/改目标、模拟支出、手动监测按钮。

### 4.3 边界（写进界面与文档）

- **只分析、只提醒，不自动转账/申购/改余额**；
- **后台节拍只做不该动钱的事**：进程内 ticker（默认 30 秒）推进预约转账、开启了监测开关的目标（默认 6 小时）、到点的计划步骤；资金动作到点只生成待确认提醒，真正扣款仍要回助手过裁决与令牌；
- 金额全部确定性计算；模型不参与算钱；
- 缺数据要用户补或显式列假设，不编造真实收支。

## 6. 安全边界是否保持完整

**执行层：完整，且更严。**

- `app/policy/rules.py` 的 `decide()` 未被知识层触碰；新增工具只做分类登记（只读/确认）。
- 三色权限、确认卡、双因子、能力令牌、参数一致性、幂等、审计哈希链、中断/回退/人工接管全部保留。
- 红队 43/43；e2e 验证 R07 红灯 + face/sms、注入备注只转 500、审计链 16 条 `chain_ok`、UPDATE 被触发器拒绝、恶意模型零工具。
- **执行层未授权资金写操作 = 0**。

**规划层：已补上多收款人/一句多笔的确定性闸门，但仍不宣称「已归零」。**

- A/B 的 `unauthorized` 口径是「该追问却没问、却把写工具列入 DAG」，不执行工具。
- 新增 `app/planner/payment_guard.py`：只看用户原话，独立于模型输出与 `KNOWLEDGE_ENABLED`；命中只追问、不建可执行写图。最终轮 A/B 两组里 C039/C044 都先追问。
- 最终轮 B 组 unauthorized=0、A 组=4；但 guard 只覆盖已识别的句式，更复杂的中文表达仍可能漏网，报告不写「已保证为零」。
- clarify 在最终有效轮是 −2.5pp：代扣解约（C006/C007/C021/C053）当时没有原话级取消信号。最终代码已补「订阅词 + 取消动词」信号与测试，但未重跑 A/B，数字未改写。
- 即便规划层漏判，执行层仍会按真实参数过策略与确认，不会因为 DAG 里多一个 transfer 就自动放行。

