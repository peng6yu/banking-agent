# 模型配置说明（换厂商 / 换模型怎么配）

> **一句话**：仓库公开、**不含任何密钥**。模型完全由你自己的 `.env` 或环境变量决定。
> 默认厂商是 MiniMax，但代码只依赖 **OpenAI 兼容协议**，换厂商只改 `.env` 三行，不用改代码。

## 0. 三十秒版

```bash
cd banking-agent
bash setup_env.sh --prompt      # 或：cp .env.example .env 后手填
# 然后在 .env 里改这三行：
#   LLM_API_KEY=你的key
```

## 1. 仓库里为什么没有我的 key

| 事实 | 在哪 |
|---|---|
| `.env` 被 gitignore 第一行挡掉，永不入库 | `.gitignore:2` |
| 代码里**没有任何默认 key**，读不到就是空串 | `app/config.py` 的 `api_key` 默认 `""` |
| key 缺失时按设计 **fail closed**，不是降级放行 | `app/llm.py` 的 `_headers()` 抛 `LLMError` |
| `setup_env.sh` 只负责把你本机的 key 抽到 `.env`（权限 600），自身不含密钥 | `setup_env.sh` |
| 仓库里查不到任何 key 形态的字符串 | 自检：`git grep -nE 'sk-[A-Za-z0-9_-]{8,}'` 无命中 |

**所以：拿到仓库的人必须自己准备一个模型 key（或用 `MOCK_MODE=script` 离线看演示）。**
这是刻意设计，不是漏传。

---

## 2. 配置从哪读（优先级）

1. **真实环境变量**（最高）
2. 仓库根目录 **`.env`**
3. 代码内**默认值**（只有 base url 和模型名，没有 key）

实现见 `app/config.py:load_env`：它用 `os.environ.setdefault` 写入 `.env` 里的键，
所以**真实环境变量永远压过 `.env`**，方便临时切模型：

```bash
LLM_MODEL=deepseek-chat python3.12 -m uvicorn app.main:app --port 8000   # 临时换模型
```

## 3. 环境变量总表

| 变量 | 作用 | 默认值 | 旧名（**仍然生效**） |
|---|---|---|---|
| `LLM_API_KEY` | 模型 API key（必填，除非 `MOCK_MODE=script`） | 空 | `MINIMAX_API_KEY` |
| `LLM_BASE_URL` | OpenAI 兼容网关 base url | `https://api.minimaxi.com` | `MINIMAX_API_HOST` |
| `LLM_ENDPOINT` | 直接指定完整 chat/completions URL（覆盖拼接规则） | 空 | — |
| `LLM_MODEL` | 主脑模型 | `MiniMax-M3.1-Flash-Preview` | `MODEL_BRAIN` |
| `LLM_MODEL_FAST` | 快模型（L2 注入分类用，生产主链路未启用） | `MiniMax-M2.5-highspeed` | `MODEL_FAST` |
| `LLM_MODEL_BACKUP` | 备脑，**只给 `app.smoke` 做思维链剥离自检**，生产链路不读、不自动降级 | `MiniMax-M2.5` | `MODEL_BACKUP` |
| `LLM_TEMPERATURE` | 采样温度 | `0` | — |
| `LLM_TIMEOUT` | 单次调用超时（秒） | `60` | `LLM_TIMEOUT_S` |
| `MOCK_MODE` | `false` 真模型 / `true` 对抗恶意桩 / `script` 离线协作桩 | `false` | — |
| `CAPABILITY_SECRET` | 能力令牌 HMAC 密钥（64 位十六进制） | 空 → 黄红灯全链路 fail closed | — |
| `SCHEDULED_TICK_MS` | 定时转账后台节拍（毫秒），`0` 关闭 | `30000` | — |

> 新名优先、旧名兜底：**老 `.env` 不用重写**。两个都写了以新名为准。
> 键名与 `app/config.py` 逐字对齐（不要照抄网上别的项目的名字，例如 `LLM_MODEL_*` 的旧错名 `LLM_TIMEOUT_S` 现在也能用了）。

## 4. base url 怎么拼成 endpoint

规则在 `app/config.py:build_endpoint`，顺序固定：

| 情况 | 例子 | 结果 |
|---|---|---|
| 给了 `LLM_ENDPOINT` | — | 直接用它，别的都不管 |
| base 已以 `/chat/completions` 结尾 | `https://x.com/v1/chat/completions` | 原样 |
| base 以 `/v1`、`/v4` 等版本号结尾 | `https://api.openai.com/v1` | `https://api.openai.com/v1/chat/completions` |
| 其余 | `https://api.deepseek.com` | `https://api.deepseek.com/v1/chat/completions` |

鉴权固定为 `Authorization: Bearer <LLM_API_KEY>`（OpenAI 兼容协议的标准做法）。

## 6. 换厂商的兼容底线（三条硬要求）

这三条是代码写死的调用方式，厂商不满足就会出问题：

1. **必须支持 `tools` + `tool_calls`**。
   本项目的结构化输出**只走 tool_calls**（实测 MiniMax 不遵守 `response_format: json_object`，所以那条路不能依赖）。
   厂商不支持工具调用 → 意图解析拿不到参数 → 全链路只会反问。
2. **必须接受 `tool_choice: "auto"`**。
   不接受会直接 400（`app/llm.py:_payload` 每次带这个字段）。
3. **必须支持 SSE 流式**（`stream: true`）。
   「决策剧场」实时侧栏依赖流式增量；不支持也能用，但 SSE 端点会退化成一次性输出。

此外，模型要能用中文理解口语金额（「五百五」「一千二」）并稳定输出合法 JSON 参数。

## 7. 配好之后怎么验（三步，缺一不可）

```bash
# ① 模型连通性自检：工具调用 / 思维链剥离 / 流式 / mock 兜底，期望 4/4 PASS
python3.12 -m app.smoke

# ② 起服务后探活，model 字段应该就是你配的模型名
python3.12 -m uvicorn app.main:app --port 8000 &
curl -s http://127.0.0.1:8000/api/health

# ③ 回归：换模型后必须重跑这三套
python3.12 -m pytest -q tests/        # 单测 + 集成
python3.12 -m scripts.redteam         # 43 条红队
python3.12 scripts/browser_smoke.py   # 浏览器级冒烟（真 Chromium）
```

`app.smoke` 输出解读：

| 行 | 含义 |
|---|---|
| `厂商/端点/主脑` | 当前生效的配置（先确认这三行！） |
| `工具调用可用` | 模型能吐 `tool_calls`，这是整个系统的地基 |
| `思维链剥离` | 适配器把 `<think>` 标签清干净了 |
| `流式可用` | SSE 增量正常，决策剧场能实时演 |
| `Mock 兜底可用` | 断网/对抗演示用的桩没坏 |

## 8. 报错速查

| 现象 | 原因 | 怎么办 |
|---|---|---|
| `模型 API key 未配置：设置 LLM_API_KEY…` | 没读到 key | 检查 `.env` 是否存在、变量名是否拼对、`bash setup_env.sh` 是否跑过 |
| `HTTP 401` | key 错，或 key 和 base url 不是同一家 | 对照第 5 节 |
| `HTTP 404` | endpoint 拼错（多半是 base url 多了/少了 `/v1`） | 看 `app.smoke` 打印的「端点」那行 |
| `HTTP 400` 且提到 `tool_choice` | 厂商不接受 `tool_choice: "auto"` | 换模型或换厂商 |
| `模型不存在 / model not found` | 模型名写错 | 查厂商的模型列表，改 `LLM_MODEL` |
| `HTTP 429` | 限流 | 已自动退避重试 3 次；换模型或降频 |
| 超时 / `网络失败` | 网络不通或模型太慢 | 调大 `LLM_TIMEOUT`；换更快的模型；本地断网时用 `MOCK_MODE=script` |
| 总是反问、参数抽不出来 | 模型不支持工具调用 | 第 6 节第 1 条；换模型 |

## 9. 换模型后必须回归的清单

```bash
python3.12 -m pytest -q tests/        # 期望全绿
python3.12 -m scripts.redteam         # 43 条红队，看通过数有没有掉
python3.12 scripts/browser_smoke.py   # 真浏览器走一遍两条主场景
```

重点盯这几种能力（换厂商最容易翻车的地方）：

- **口语金额**：「五百五」「一千二」能不能解析成 550 / 1200
- **同名收款人**：该反问时必须反问，不能瞎选人（安全相关，红队会查）
- **工具参数 JSON**：`amount` 要整数分、`card_tail` 要四位字符串，错一位就是钱的事
- **思维链**：有的模型会把 `<think>` 混在 `content` 里，适配器会剥，但要确认剥干净

## 10. 密钥安全铁律

- key 只进 `.env`（权限 600）或环境变量，**永不进代码、文档、截图、提交物**
- `.env` 已在 `.gitignore`；万一误提交过：`git rm --cached .env` 并**立刻轮换 key**
- 答辩现场用 `MOCK_MODE=script` 时全程零网络，key 不出场
- 截图里的终端输出注意别把 `.env` 内容框进去

## 11. 常见问题

**Q：为什么不把 key 写进代码/配置默认值？**
A：这是 fail-closed 设计的一部分。key 缺失时黄灯/红灯链路直接停摆（`MISSING_CAPABILITY`），
而不是拿一个默认 key 悄悄跑。绿灯只读查询不依赖该密钥，仍然可用。

**Q：能同时配多家、失败自动降级吗？**
A：目前不自动降级。`LLM_MODEL_BACKUP` 只给 `app.smoke` 做思维链剥离自检用，生产链路不读它。
自动降级属于后续待办，本仓库如实标注。

**Q：`MOCK_MODE=true` 和 `MOCK_MODE=script` 有什么区别？**
A：`true` 是**对抗演示专用**的恶意模型桩（固定吐「转出全部余额到陌生账户」），用来现场演示
「模型被劫持也动不了一分钱」，**不能拿去演普通问答**（问什么都是「我听不懂」）；
`script` 是离线协作回放桩，纯规则、确定性、零网络，只回放「查余额」与「转账」两种业务。

**Q：`app.smoke` 说 4/4 PASS，但演示还是不对？**
A：smoke 只验模型连通性与协议能力，不验业务正确性。业务还要跑第 7 节的 ③ 三套回归。
