# 模型配置说明（换厂商 / 换模型怎么配）

> **一句话**：仓库公开、**不含任何密钥**。模型完全由你自己的 `.env` 或环境变量决定。
> 默认厂商是 MiniMax，但代码只依赖 **OpenAI 兼容协议**，换厂商只改 `.env` 三行，不用改代码。

## 1. 仓库里为什么没有我的 key

| 事实 | 在哪 |
|---|---|
| `.env` 被 gitignore 第一行挡掉，永不入库 | `.gitignore:2` |
| 代码里**没有任何默认 key**，读不到就是空串 | `app/config.py` 的 `api_key` 默认 `""` |
| key 缺失时按设计 **fail closed**，不是降级放行 | `app/llm.py` 的 `_headers()` 抛 `LLMError` |
| `setup_env.sh` 只负责把你本机的 key 抽到 `.env`（权限 600），自身不含密钥 | `setup_env.sh` |
| 仓库里查不到任何 key 形态的字符串 | 自检：`git grep -nE 'sk-[A-Za-z0-9_-]{8,}'` 无命中 |

**所以：拿到仓库的人必须自己准备一个模型 key（或用 `MOCK_MODE=script` 离线看演示）。**
这是刻意设计，不是漏传。

---

## 2. 配置从哪读（优先级）

1. **真实环境变量**（最高）
2. 仓库根目录 **`.env`**
3. 代码内**默认值**（只有 base url 和模型名，没有 key）

实现见 `app/config.py:load_env`：它用 `os.environ.setdefault` 写入 `.env` 里的键，
所以**真实环境变量永远压过 `.env`**，方便临时切模型：

```bash
LLM_MODEL=deepseek-chat python3.12 -m uvicorn app.main:app --port 8000   # 临时换模型
```

## 3. 环境变量总表

| 变量 | 作用 | 默认值 | 旧名（**仍然生效**） |
|---|---|---|---|
| `LLM_API_KEY` | 模型 API key（必填，除非 `MOCK_MODE=script`） | 空 | `MINIMAX_API_KEY` |
| `LLM_BASE_URL` | OpenAI 兼容网关 base url | `https://api.minimaxi.com` | `MINIMAX_API_HOST` |
| `LLM_ENDPOINT` | 直接指定完整 chat/completions URL（覆盖拼接规则） | 空 | — |
| `LLM_MODEL` | 主脑模型 | `MiniMax-M3.1-Flash-Preview` | `MODEL_BRAIN` |
| `LLM_MODEL_FAST` | 快模型（L2 注入分类用，生产主链路未启用） | `MiniMax-M2.5-highspeed` | `MODEL_FAST` |
| `LLM_MODEL_BACKUP` | 备脑，**只给 `app.smoke` 做思维链剥离自检**；自动降级请用下面两个变量 | `MiniMax-M2.5` | `MODEL_BACKUP` |
| `LLM_FALLBACK` | **降级链（同厂商）**：主模型不可用时按顺序切过去的模型名，逗号分隔 | 空（不降级） | — |
| `LLM_FALLBACK_VENDORS` | **降级链（跨厂商）**：`base_url::模型名::KEY_ENV_NAME`，逗号分隔；第三段是**环境变量名**，配置文件里不出现密钥 | 空（不降级） | — |
| `LLM_TEMPERATURE` | 采样温度 | `0` | — |
| `LLM_TIMEOUT` | 单次调用超时（秒） | `60` | `LLM_TIMEOUT_S` |
| `MOCK_MODE` | `false` 真模型 / `true` 对抗恶意桩 / `script` 离线协作桩 | `false` | — |
| `CAPABILITY_SECRET` | 能力令牌 HMAC 密钥（64 位十六进制）。**未设置**时首次运行自动生成到 `data/token_secret`（0600）并复用；**设置了**就只认合法十六进制，否则黄红灯 fail closed | 自动生成 | — |
| `CAPABILITY_SECRET_FILE` | 自动生成密钥的落盘路径 | `data/token_secret` | — |
| `CONFIRM_TIMEOUT_S` | 确认卡等待窗口（秒），10—3600，非法值回落 120 | `120` | — |
| `SCHEDULED_TICK_MS` | 定时转账后台节拍（毫秒），`0` 关闭 | `30000` | — |

> 新名优先、旧名兜底：**老 `.env` 不用重写**。两个都写了以新名为准。
> 键名与 `app/config.py` 逐字对齐（不要照抄网上别的项目的名字，例如 `LLM_MODEL_*` 的旧错名 `LLM_TIMEOUT_S` 现在也能用了）。

## 4. base url 怎么拼成 endpoint

规则在 `app/config.py:build_endpoint`，顺序固定：

| 情况 | 例子 | 结果 |
|---|---|---|
| 给了 `LLM_ENDPOINT` | — | 直接用它，别的都不管 |
| base 已以 `/chat/completions` 结尾 | `https://x.com/v1/chat/completions` | 原样 |
| base 以 `/v1`、`/v4` 等版本号结尾 | `https://api.openai.com/v1` | `https://api.openai.com/v1/chat/completions` |
| 其余 | `https://api.deepseek.com` | `https://api.deepseek.com/v1/chat/completions` |

鉴权固定为 `Authorization: Bearer <LLM_API_KEY>`（OpenAI 兼容协议的标准做法）。

## 6. 换厂商的兼容底线（三条硬要求）

这三条是代码写死的调用方式，厂商不满足就会出问题：

1. **必须支持 `tools` + `tool_calls`**。
   本项目的结构化输出**只走 tool_calls**（实测 MiniMax 不遵守 `response_format: json_object`，所以那条路不能依赖）。
   厂商不支持工具调用 → 意图解析拿不到参数 → 全链路只会反问。
2. **必须接受 `tool_choice: "auto"`**。
   不接受会直接 400（`app/llm.py:_payload` 每次带这个字段）。
3. **必须支持 SSE 流式**（`stream: true`）。
   「决策剧场」实时侧栏依赖流式增量；不支持也能用，但 SSE 端点会退化成一次性输出。

此外，模型要能用中文理解口语金额（「五百五」「一千二」）并稳定输出合法 JSON 参数。

## 7. 配好之后怎么验（四步，缺一不可）

```bash
# ① 协议能力自检（换任何厂商先跑这个）：连通性 / tool_calls / tool_choice:auto / SSE 收尾
#    期望 4/4 PASS，退出码 0
python3.12 -m scripts.provider_check
#    想先试别家、还没改 .env？用参数覆盖（key 仍然只从环境变量读，命令行不许传 key）
python3.12 -m scripts.provider_check --base-url https://api.deepseek.com --model deepseek-chat

# ② 业务侧连通性自检：工具调用 / 思维链剥离 / 流式 / mock 兜底，期望 4/4 PASS
python3.12 -m app.smoke

# ③ 起服务后探活，model 字段应该就是你配的模型名
python3.12 -m uvicorn app.main:app --port 8000 &
curl -s http://127.0.0.1:8000/api/health

# ④ 回归：换模型后必须重跑这三套
python3.12 -m pytest -q tests/        # 单测 + 集成
python3.12 -m scripts.redteam         # 43 条红队
python3.12 scripts/browser_smoke.py   # 浏览器级冒烟（真 Chromium）
```

`scripts.provider_check` 做四件事，任一不过就说明这家厂商不能直接换上来：

| 检查项 | 通过意味着 | 不过的典型原因 |
|---|---|---|
| 连通性 | endpoint 通、返回 `choices` 数组 | base url/endpoint 拼错、403 地区限制 |
| `tool_calls` | 带 `tools` 时模型真吐工具调用 | 厂商不支持 function calling |
| `tool_choice:"auto"` | 不因这个字段报 400 | 只接受 `"none"`/`"required"` |
| SSE 流式收尾 | 有 `data:` 行、`delta.content` 非空、以 `finish_reason` 收尾 | 只认 `data: [DONE]`、或流式不带增量 |

> 注意：这个脚本会真实消耗 4 次厂商额度；输出里 key 一律打码（JSON 模式只有 `api_key_configured` 布尔）。

`app.smoke` 输出解读：

| 行 | 含义 |
|---|---|
| `厂商/端点/主脑` | 当前生效的配置（先确认这三行！） |
| `工具调用可用` | 模型能吐 `tool_calls`，这是整个系统的地基 |
| `思维链剥离` | 适配器把 `<think>` 标签清干净了 |
| `流式可用` | SSE 增量正常，决策剧场能实时演 |
| `Mock 兜底可用` | 断网/对抗演示用的桩没坏 |

## 8. 报错速查

| 现象 | 原因 | 怎么办 |
|---|---|---|
| `模型 API key 未配置：设置 LLM_API_KEY…` | 没读到 key | 检查 `.env` 是否存在、变量名是否拼对、`bash setup_env.sh` 是否跑过 |
| `HTTP 401` | key 错，或 key 和 base url 不是同一家 | 对照第 5 节 |
| `HTTP 404` | endpoint 拼错（多半是 base url 多了/少了 `/v1`） | 看 `app.smoke` 打印的「端点」那行 |
| `HTTP 400` 且提到 `tool_choice` | 厂商不接受 `tool_choice: "auto"` | 换模型或换厂商 |
| `模型不存在 / model not found` | 模型名写错 | 查厂商的模型列表，改 `LLM_MODEL` |
| `HTTP 429` | 限流 | 已自动退避重试 3 次；换模型或降频 |
| 超时 / `网络失败` | 网络不通或模型太慢 | 调大 `LLM_TIMEOUT`；换更快的模型；本地断网时用 `MOCK_MODE=script` |
| 总是反问、参数抽不出来 | 模型不支持工具调用 | 第 6 节第 1 条；换模型 |

## 9. 换模型后必须回归的清单

```bash
python3.12 -m pytest -q tests/        # 期望全绿
python3.12 -m scripts.redteam         # 43 条红队，看通过数有没有掉
```

重点盯这几种能力（换厂商最容易翻车的地方）：

- **口语金额**：「五百五」「一千二」能不能解析成 550 / 1200
- **同名收款人**：该反问时必须反问，不能瞎选人（安全相关，红队会查）

- **思维链**：有的模型会把 `<think>` 混在 `content` 里，适配器会剥，但要确认剥干净

## 11. 常见问题

**Q：为什么不把 key 写进代码/配置默认值？**
A：这是 fail-closed 设计的一部分。key 缺失时黄灯/红灯链路直接停摆（`MISSING_CAPABILITY`），
而不是拿一个默认 key 悄悄跑。绿灯只读查询不依赖该密钥，仍然可用。

**Q：能同时配多家、失败自动降级吗？**
A：可以，见第 12 节。同厂商换模型用 `LLM_FALLBACK`，跨厂商用 `LLM_FALLBACK_VENDORS`
（密钥只写环境变量名，不写进配置串）。`LLM_MODEL_BACKUP` 仍然只给 `app.smoke` 自检用，与降级链无关。

**Q：`MOCK_MODE=true` 和 `MOCK_MODE=script` 有什么区别？**
A：`true` 是**对抗演示专用**的恶意模型桩（固定吐「转出全部余额到陌生账户」），用来现场演示
「模型被劫持也动不了一分钱」，**不能拿去演普通问答**（问什么都是「我听不懂」）；
`script` 是离线协作回放桩，纯规则、确定性、零网络，只回放「查余额」与「转账」两种业务。

**Q：`app.smoke` 说 4/4 PASS，但演示还是不对？**
A：smoke 只验模型连通性与协议能力，不验业务正确性。业务还要跑第 7 节的 ③ 三套回归。

## 12. 降级链：主目标不可用时自动换下一个

主模型 401/超时/5xx 时，整条链路不该跟着停摆。降级链按配置顺序逐个尝试，
**只有明确"换个目标还有救"的错误才切**，请求体本身不合法就立刻抛错，不做无用功。

### 12.1 两个变量

```bash
# ① 同厂商降级：同一个 base url、同一把 key，只换模型名（最省事，先上这个）
LLM_FALLBACK=MiniMax-M2.5-highspeed,MiniMax-M2.5

# ② 跨厂商降级：base_url::模型名::KEY_ENV_NAME（第三段是环境变量名，不是密钥）
LLM_FALLBACK_VENDORS=https://api.deepseek.com::deepseek-chat::DEEPSEEK_API_KEY,https://dashscope.aliyuncs.com/compatible-mode/v1::qwen-plus::DASHSCOPE_API_KEY
```

两个变量可以同时用：尝试顺序 = 主目标 → `LLM_FALLBACK` 里的模型 → `LLM_FALLBACK_VENDORS` 里的厂商。
同一个 `base url + 模型名` 只会被试一次（写了重复也无害）。

### 12.2 什么错会切、什么错不切

| 错误类别 | 例子 | 切下一个目标？ |
|---|---|---|
| 连接/超时 | 连不上、DNS 失败、读超时 | ✅ 切 |
| 鉴权失败 | HTTP 401/403 | ✅ 切（多半是这家 key 过期或地区限制） |
| 模型不存在 | HTTP 404 | ✅ 切（模型名写错/下线） |
| 限流 | HTTP 429 | ✅ 切（并带上原有的退避重试） |
| 服务端故障 | HTTP 5xx | ✅ 切 |
| **请求体不合法** | **HTTP 400 / 422** | ❌ **不切**，直接抛错——换厂商同样会 400，藏着反而更难查 |

### 12.3 密钥怎么放

- 跨厂商条目的密钥**只从环境变量读**（`KEY_ENV_NAME` 指向的那个变量），
  配置串里永远只有变量名；`.env` 里各家的 key 照旧单独一行。
- 目标没配到 key 时，报错会点名是哪个降级目标缺 key，且**不会**把 key 打到日志/错误里
  （切换日志 `llm.fallback.switch`、最终报错里的失败摘要都会先抹 key）。
- 全部目标失败时抛 `LLMError`，消息逐条列出「目标 / base / 模型 / 错误类别」，同样不含 key。

### 12.4 怎么确认真的降级了

| 观测点 | 看什么 |
|---|---|
| `LLMResponse.served_by` | `primary` / `fallback:<模型名>` / `vendor:<base url>`，真正服务的那一个 |
| `LLMResponse.served_endpoint` | 实际请求的完整 URL |
| 日志事件 `llm.fallback.switch` | 切换时打一条：原目标 base/模型、错误类型/类别/状态码、下一个目标 |
| `python3.12 -m app.smoke` | 输出「厂商/端点/主脑」那几行，确认当前生效配置 |

### 12.5 两条注意事项

1. 降级目标也必须满足第 6 节的三条硬要求（`tools`/`tool_choice:"auto"`/SSE），
   换之前先用 `scripts.provider_check` 验一遍。
2. 降级只换「谁回答」，不换业务语义：工具定义、系统提示词、审计口径都不变；
   如果某家模型抽参数明显更差，红队与 `pytest` 要重跑（第 7 节 ④）。

## 13. 本地 Ollama：零成本、断网也能验的第二个厂商

第 12 节的降级链我用它在真机上验过（MiniMax 配额耗尽 429 → 自动切 Ollama 正常出话）。
它同时是「不想花钱 / 没有别家 key / 想离线演示」时最省事的第二厂商。

### 13.1 准备

```bash
# 1) 装 Ollama（官网一键脚本，或系统包管理器）
curl -fsSL https://ollama.com/install.sh | sh

# 2) 拉一个支持工具调用的模型；显存 8GB 用 7b，只有 CPU 或想快就用 0.5b
ollama pull qwen2.5:7b      # 质量优先
ollama pull qwen2.5:0.5b    # 速度优先，本仓库实测用的这个

# 3) 确认 OpenAI 兼容端点活着（默认监听 11434，/v1 前缀由 Ollama 提供）
curl -s http://127.0.0.1:11434/v1/models | head -c 300
```

### 13.2 填 .env

```bash
LLM_BASE_URL=http://127.0.0.1:11434/v1
LLM_MODEL=qwen2.5:0.5b
LLM_MODEL_BACKUP=qwen2.5:0.5b    # app.smoke 第 2 项校验的是备份模型，别漏
LLM_MODEL_FAST=qwen2.5:0.5b
LLM_API_KEY=ollama-local         # Ollama 不校验 key，但配置层要求非空
MOCK_MODE=false
```

> `LLM_API_KEY` 随便填个非空串即可。**别把真实云端 key 留在这里**，否则本地跑通后
> 降级链会拿它去打云端，账算不清。

### 13.3 验（两步，和云端同一套标准）

```bash
LLM_API_KEY=ollama-local python3.12 -m scripts.provider_check \
  --base-url http://127.0.0.1:11434/v1 --model qwen2.5:0.5b
python3.12 -m app.smoke
```

本机实测（2026-10-23，RTX 4060 Laptop / 8GB）：

| 检查 | 结果 |
|---|---|
| provider_check 四项 | **4/4 PASS**：连通 200 / 144ms；工具调用返回 1 个 `query_balance`；接受 `tool_choice:"auto"` 未被 400；SSE 18 条 data 行、`finish_reason=stop`（Ollama 不吐 `[DONE]`，解析层已兼容） |
| app.smoke 四项 | **4/4 PASS** |
| 真降级链 | MiniMax 返回 429（Token Plan 配额耗尽）→ 日志 `llm.fallback.switch` status=429 → `served_by=vendor:http://127.0.0.1:11434/v1`，275ms，正常出话 |

### 13.4 当降级目标用

```bash
# 主目标仍是云端，云端挂了落到本机 Ollama
LLM_FALLBACK_VENDORS='http://127.0.0.1:11434/v1::qwen2.5:0.5b::OLLAMA_KEY'
OLLAMA_KEY=ollama-local
```

格式还是第 12.1 节的 `base_url::模型名::KEY_ENV_NAME`，key 用独立的
`OLLAMA_KEY`，不复用云端那把。

### 13.5 本地小模型的真实下限

0.5b 能过协议层四关（这是硬指标，很多自建服务过不了），但**业务准确率明显不如云端**：
中文长句里抽金额/收款人容易漏，同名收款人的澄清轮也可能答非所问。它适合

- 验证「换厂商能不能跑」这件事本身；
- 断网/演示现场兜底；
- 省钱的回归跑（`pytest` 与红队不依赖真实模型，跑它们不需要 Ollama）。

**不适合**当答辩主模型。要本地跑得好看，至少上 7b 以上（视显存），并把
第 9 节「换模型后必须回归的清单」全跑一遍；模型能力不够时优先让它做备份而不是主脑。
