## 1. 赛题背景

- 传统手机银行操作路径长、功能入口深，用户完成一笔转账平均需要 **3 步以上**操作。
- 随着多模态大模型和 Agent 技术成熟，“说话就能办业务”正从概念走向现实。
- 要求参赛团队构建一个 **银行 AI 智能体（AI Banking Agent）**：用户只需用自然语言描述需求，Agent 即可自主理解意图、规划任务链路，并在**严格的安全框架内**完成银行业务操作。
- 可参考 **OpenClaw** 等开源智能体项目。
- 行业对标：**Revolut AIR**（Revolut 推出的 AI 银行助手）。鼓励探索更深入的场景覆盖与更流畅的交互体验。

## 2. 赛题任务

构建一个 AI Banking Agent 系统：
- 通过自然语言对话理解用户金融意图；
- 自主规划并执行银行业务操作；
- 用户可通过 **APP、IM** 等渠道与 Agent 联通；
- **至少覆盖下列 3 个核心场景（鼓励全覆盖）**，下表仅作参考：

| 序号 | 场景方向 | 典型能力示例 |
|---|---|---|
| 1 | 智能转账 | 按人名、手机号或备注转账；定时转账；拆分 AA 收款 |
| 2 | 账单分析 | 消费分类统计；异常交易识别；月度 / 年度账单报告 |
| 3 | 理财操作 | 产品推荐与对比；风险评估；一键申购 / 赎回 |
| 4 | 卡片管理 | 卡申请；额度调整；交易限制 / 解锁；卡片挂失 |
| 5 | 订阅 / 代扣管理 | 自动识别订阅扣费；续费提醒；一键取消订阅 |
| 6 | 跨场景联动 | 检测“我爱人生日”，当月锁定 1000 元活期，生日前 2 天订购鲜花、蛋糕 |

> **范围决策建议**：6 选 3 是硬门槛，但场景之间有依赖 —— 场景 2（账单分析）与 3（理财操作）共用账户与流水数据，场景 4/5 复用同一套卡片与代扣工具链，场景 6 需要前序能力做编排。优先选 1 + 2 + 6，可用一套账户/流水/风控内核打通三个场景，演示时故事线也最完整。

## 3. 核心技术要求

### 3.1 权限分级机制（实现优先级：**高**）

系统必须建立严格的操作权限分级体系，体现“**低风险自动、高风险确认、极高风险强验证**”的安全理念：

| 级别 | 执行策略 | 典型操作范围 |
|---|---|---|
| 🟢 绿色 | **自动执行** | 余额查询、交易记录查询、账单分析、理财收益查询等纯查询类操作。Agent 确认意图后直接执行，**无需二次确认** |
| 🟡 黄色 | **用户确认** | 小额转账（**日累计 ≤ 1000 元**）、订阅查询 / 取消、虚拟卡申请等。执行前展示操作详情并获得明确确认 |
| 🔴 红色 | **强验证** | 大额转账（**日累计 > 1000 元**）、密码修改、卡片挂失 / 解挂、理财产品申购等。须通过**人脸识别、短信验证码或 U 盾**等多因子认证 |

> 注意黄/红的分界是**日累计 1000 元**，且“日累计”意味着分级不能只看单笔 —— 需要一个按用户维度的日累计额度状态机。

### 3.2 安全机制（实现优先级：**高**）

- **幻觉防护**：Agent 不得编造交易结果或账户信息；
- **注入防御**：防止通过特殊 Prompt 绕过权限控制；
- **操作审计**：所有关键操作需记录完整的决策链路与执行日志；
- **异常熔断**：连续失败或可疑行为触发安全锁定；
- **沙箱环境**：生成的代码在受限、可监控的逻辑隔离环境中运行。

### 3.3 意图理解与任务规划

- 支持模糊表达、省略上下文、隐含意图的识别；
- 复杂任务需拆解为有序的**子任务 DAG（有向无环图）**；
- 执行过程中支持**中断、回退和人工接管**。

## 4. 评审规则

| 权重 | 维度 | 考察点 |
|---|---|---|
| **40%** | 任务完成率 | 典型金融场景任务的完成情况、多步骤任务规划合理性及工具调用正确性 |
| **30%** | 安全合规性 | 对**诱导转账、信息套取、越权操作和 Prompt 注入**等风险的防御能力，以及敏感操作确认和风险提示 |
| **30%** | 创新性及交互体验 | 场景新颖性、真实问题解决度、对话轮次效率、追问能力、错误恢复、口语化输入和超范围兜底 |

> **怎么用这个权重排优先级**：安全合规性与创新体验并列 30%，意味着安全不是“附加项”而是**三分之一的分数**。答辩演示必须把红黄绿分级切换、注入对抗实拍、审计日志回放当成主线来演，不能只演示 happy path。
