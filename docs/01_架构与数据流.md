# 01 架构与数据流

## 1.1 三段论（整个方案的骨架）

```
用户（APP / IM）
   │  自然语言 + 结构化指令
   ▼
[入口] envelope.wrap()          ← 外部字符串一律降级为数据
   ▼
[不可信区] LLM                  意图解析、DAG 规划、话术生成
   │  产出：结构化 action（不是代码、不是 SQL、不是金额指令）
   ▼
[裁决区] PolicyEngine.decide()  纯函数、无网络、无模型、可单测
   │  产出：green / yellow(+确认) / red(+因子) + capability_token
   ▼
[执行区] tools.*(token, params) 校验 token → 落账 → 银行核心(mock)
   ▼
[账本] audit.append()           每步一条，链式哈希
   ▼
[呈现] SSE → 决策剧场（右栏五块实时面板）
```

## 1.2 五个不变量

1. **模型输出永不直接执行。** 模型只能产出 `Action` 数据结构，必须过裁决区。
2. **每次执行都有 token，且 token 绑定参数哈希。** 改了金额、改了收款人，token 立即失效。
3. **资金变动必经 hold→commit 或 hold→release。** 不存在直接扣款路径。
4. **每个状态变更都写审计，链可验证。** 断链 = 篡改。
5. **任何时刻可中断，中断后资金不悬空。** 所有 hold 带过期时间，后台清扫。

## 1.3 一次转账的完整时序

| 步 | 组件 | 动作 | 失败分支 |
|---|---|---|---|
| 1 | 前端 | 用户输入：转 500 给张三，备注 生日快乐 | — |
| 2 | envelope | 标记 `source=user`，备注字段标记 `untrusted=true` | 长度超限 → 截断并告警 |
| 3 | intent | 调 `emit_intent` 工具 → `{intent:transfer, slots:{payee:张三, amount_fen:50000, note:生日快乐}, missing:[]}` | 没调工具 → 重试 1 次 → 转澄清提问 |
| 4 | intent | 校验槽位完整性 | 缺收款人 → 反问；缺金额 → 反问；收款人重名 → 列候选 |
| 5 | planner | 生成 DAG：`resolve_payee → check_balance → transfer` | 有环 → 报错并降级为单步 |
| 6 | executor | 逐节点取 action，调 `engine.decide()` | 规则表未命中 → 默认 red（默认拒绝） |
| 7 | policy | 第 3 节点判定 yellow（500 元 < 1000 元） | — |
| 8 | executor | 暂停，SSE 发 `confirm` 事件，携带人话解释 | 用户 120 秒未确认 → 取消并审计 |
| 9 | policy.token | 用户确认后签发 token：绑定 `tool=transfer, params_hash, amount_fen, ttl=120s, nonce` | 签发失败 → 500 并审计 |
| 10 | tools.transfers | `initiate(token, params)`：校验 token → 校验余额 → 写入 hold（带 idempotency_key） | 余额不足 → `InsufficientFunds`；重复提交 → 幂等键命中，返回原 hold |
| 11 | tools.transfers | `commit(hold_id)` | hold 已过期 → 拒绝并提示重新发起 |
| 12 | audit | 写 `transfer.initiated` + `transfer.committed` 两条 | 写失败 → 事务回滚，钱不动 |
| 13 | sse | 发 `done` 事件，剧场右栏落到终态 | — |

## 1.4 模块依赖方向（禁止反向）

W4 之后依赖方向按**层号**读：数字大的可以 import 数字小的，反过来要倒置（注册表或仓储），不许加豁免。层号写在 `tests/test_imports.py` 的 `LAYERS` 里，是最权威的一份。

| 层 | 有哪些模块 | 能做什么 | 明令禁止 |
|---|---|---|---|
| L5 api / views | `app/api/*`（含装配门面 `routes.py` 与 9 个分组模块）、`app/views/*`、`app/handoffs.py`、`app/planner/*` | 解析请求、编排一次对话、装配只读视图、要动执行器的恢复与取消 | 在路由里写 SQL / 开事务 / 直调工具写函数；视图写库 |
| L4 用例 | `app/use_cases/*` | 一个写操作 = 一个事务 + 一个 `Outcome`，异常只在这里翻译一次 | 收 `app.api.schemas` 的模型、自己发 HTTP 话术 |
| L3 领域 | `app/birthday.py` `app/plans.py` `app/proactive.py` `app/funds.py` `app/subscriptions.py` 等 | 业务规则、表读写、审计 | import policy / tools / planner |
| L2 仓储 | `app/handoff_store.py` | 单张聚合表的状态迁移与快照，只认 `audit` / `clock` / `db` / `ids` | 认识 planner 与 api（原来 handoffs 两头都要，是两条反向依赖） |
| L2 policy | `app/policy/*` | 纯函数裁决、签发凭据 | 网络、模型、随机 |
| L1 基础设施 | `app/db.py` `app/audit.py` `app/clock.py` `app/ids.py` `app/timefmt.py` `app/chat_history.py` `app/plan_hooks.py` | 连接与事务、审计链、时间、时间串、会话记忆、**钩子注册表** | 认识任何业务模块 |
| L1 tools | `app/tools/*` | 校验 token、动资金对象 | import planner |
| L0 kernel | 标准库与常量 | — | — |

| 约束 | 说明 | 检查 |
|---|---|---|
| policy 不许 import llm | 裁决区严禁依赖模型 | `tests/test_imports.py` |
| tools 不许 import planner | 执行层不知道有规划这回事 | 同上 |
| db 不许 import 任何上层 | 最底层 | 同上 |
| 不许有反向依赖 | 豁免表 `UPWARD_EXCEPTIONS` **必须为空**：要通知下层改上层时用注册表（`plan_hooks`），要跨层取数时抽仓储（`handoff_store`） | 同上 + `scripts/arch_report.py`「跨层违规 0 条」 |
| 全项目禁止循环 import | — | 同上 |

## 1.5 组件职责一览

| 组件 | 一句话职责 | 允许做 | 禁止做 |
|---|---|---|---|
| `envelope` | 给外部字符串贴来源标签 | 截断、转义、标记 | 判断业务意图 |
| `intent` | 把自然语言变成结构化槽位 | 调 LLM、重试、反问 | 直接执行 |
| `dag` | 把槽位变成可执行步骤图 | 校验、拓扑排序 | IO |
| `executor` | 按拓扑跑步骤 | 调 policy、调 tools、发事件 | 自己决定颜色 |
| `policy.engine` | 唯一裁决者 | 纯计算 | 网络、模型、随机 |
| `policy.token` | 签发/校验凭据 | HMAC、比对 | 存数据库（无状态） |
| `tools.*` | 真正动数据和钱 | 校验 token、事务 | 判断该不该做 |
| `audit` | 记账 | 追加、验证链 | 修改历史 |
| `api` | 对外 HTTP/SSE | 拼装、流式输出 | 业务逻辑 |
| `web/index.html` | 呈现 | 展示、发请求 | 参与决策 |
