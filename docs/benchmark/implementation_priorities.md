# 改造实施优先级（阶段 0.5）

> **用途**：把 `docs/benchmark/air_vs_banking_agent.md` 的 17 个缺口（G01–G17）收敛成一份可执行的排期：做什么、不做什么、先做哪条、怎么验收、来不及怎么退。
> **口径**：缺口编号、证据等级、代码位置均引用差距矩阵，不在此重复论证；本项目状态以 2026-10-25 **最终全量回归**（**1669 passed / 4 skipped**、红队 **PASS 43 / FAIL 0**、e2e **13/13**、浏览器旅程 **7/7**）为准。改造过程中出现过的 916/935/1336 等中间态数字只作**历史基线**，**不作为交付数字**。
>
> **本轮修订（2026-10-24 审计整改）**：G15（人工接管）已由「否」改为「是（收窄版：本地操作员队列，不对接坐席系统）」，落地范围与验收见 §1.6；G10 仍为 P2，但真实 MFA 通道尚未接入这一限制已在安全自评报告与 README 中显式声明。
> **一句话结论**：10 天窗口内只做 **6 个 P0 的收窄版（21 人日）+ 3 个低成本 P1（4 人日）**，共 25 人日、3 人并行约 8.5 天；**不引入向量库、图数据库、多 Agent 框架**，不碰真实银行认证与多租户。

## 二、功能取舍

### 2.1 三条取舍原则

1. **能证明"敢动钱"的优先**：安全内核（令牌七步、规则、审计、熔断）已有且是最高分项，本次只做"不破坏 + 可解释化"，不重构。
2. **赛题六场景优先于 AIR 对标**：AIR 的旅行生态（eSIM/Stays）与本项目定位无关，直接放弃；AIR 的"投资只读"与赛题冲突，按 E4 做**有意偏离 + 补偿控制**，并在文档声明。
3. **证据优先于功能数量**：G13 评测集、G12 来源引用、G11 数据地图都是"答辩可验证"的低成本高回报项，优先级高于 G02/G04/G08 这类体验增强。

### 2.2 P0 收窄口径（全量 → 本次）

| 缺口 | 全量做法 | 本次收窄 | 砍掉的部分及影响 |
|---|---|---|---|
| G14 | 5 个 YAML 全量 + 4 处接线 + 完整冲突消解 | terms 60 条（原 80–120）、workflows 只覆盖 6 场景、接线 3 处（检索/注入/审计）、冲突只降级不自动合并 | 长尾术语与跨文档冲突合并；答辩时说明"知识层是可扩展数据层" |
| G12 | 逐结论引用 + 前端来源面板 + 多来源排序 | 只做"规则号 + 来源 ID + 三档状态"三件事 | 来源排序/权重；不影响"可追溯"结论 |
| G05 | 识别 + 提醒 + 暂停状态 + 后台定时扫描 | 识别 + 一次性提醒 + 手动触发扫描；**不做 paused** | 后台常驻提醒；演示改为"打开即见提醒" |
| G06 | 问卷 + 匹配 + 推荐排序 + 对比表 + 收益报表 | 问卷 + 拒售/强提示 + 对比表 | 推荐排序算法、收益报表；场景 3 仍完整 |
| G07 | 通用计划层（任意目标组合）+ 断点续跑 | 生日复合计划（5 节点）+ 预算互斥 + 重发未完成节点 | 任意组合的通用性；用"模板可扩展"话术兜底 |
| G13 | 200+ 句 + CI 门禁 + 在线抽样 | 80 句 + 本地脚本 + 报告 | 在线质量抽样；足够支撑 40% 完成率举证 |

### 2.3 取舍后的能力边界（对外话术必须一致）

- 能做：六场景全覆盖的**单用户演示**；知识增强的意图理解；来源可追溯的决策解释；订阅识别与提醒；适当性拒售；跨场景复合计划。
- 不能做：真实多因子认证、多租户、7×24 主动推送、第三方系统接入、投资建议。
- 不宣称：不称"对标 AIR 的主动顾问"，不称"用了 RAG/向量库"，不称"已对接银行认证"。

## 三、演示故事（1 主 + 2 辅，合计约 5 分钟）

### 3.1 主故事：生日跨天计划 + 账单 + 订阅（场景 6 + 2 + 5，分步演示）

> **重要修正（2026-10-24）**：旧版主故事把「预留 1000 元生日预算」和「把同一笔 1000 元买成理财」写进同一句，这与资金层冲突——`plan_budgets` 的有效预算会从 `available_fen` 中扣除，同一笔钱不能再申购。旧故事已废弃。

**用户原话（一句）**：
> "下个月 15 号是我爱人生日，这个月先帮我留 1000 元预算，生日前 2 天提醒我订鲜花和蛋糕；再看看最近三个月账单有哪些异常、未来 7 天有哪些订阅要扣。"

**期望系统行为（分步演示，不承诺一句话生成统一 5 节点 DAG）**：

| 步 | 系统动作 | 权限 | 可验证点 |
|---|---|---|---|
| 1 | 建生日计划：预算 1000 元，鲜花 400 / 蛋糕 600，生日前两天 09:00 触发 | 黄（确认） | `plans` / `plan_budgets` 落库；余额不变；刷新后仍在（J4） |
| 2 | 账单异常：月/年分类、Top 商户、三类异常 | 绿 | 只读；每条异常带依据流水 |
| 3 | 订阅推断 + 近 7 天可能扣费 | 绿 | `inferred` 带置信度与证据笔；`upcoming` 只展示，不推送 |
| 4 | 到点检查 + 提醒；可选一次性授权（绑定计划版本+项目+金额） | 黄 / 红 | 到点只提醒，付款重新确认；风险升级红则暂停 |

**口径**：这是同一会话里的多轮自然语言演示，**不承诺一句话自动完成三类任务**；不演示「同一笔预算再买理财」，也不演示「未经用户确认直接取消订阅」。

### 3.2 辅助故事 1：转账 + AA + 定时 + 账单（场景 1 + 2，约 1.5 分钟）

> "给小王转 200，备注聚餐；上周那顿 360 我们仨 AA；以后每月 1 号给房东转 3000；顺便看看上个月钱花哪了，有没有异常。"

覆盖：人名/备注转账、AA 三人拆分（总额守恒）、月度定时、账单分类 + 3 类异常（`split_orders/odd_hour_overseas/subscription_hike`）。验收锚点：`tests/test_split.py`（8 条含"分不丢一分钱"）、`test_scheduled.py`、`bill.py:192`。

### 3.3 辅助故事 2：卡片 + 订阅（场景 4 + 5，约 1.5 分钟）

> "我卡好像丢了，先挂失；再给我开一张单次虚拟卡，限额 500；对了，我刚看到有个视频会员还在扣钱，帮我查查并退掉。"

覆盖：挂失（红/三因子）、虚拟卡（黄/单次）、限额、订阅查询 + 取消 + 识别证据。验收锚点：`test_cards_close_pin.py`、`test_tools_cards.py`、`test_subscription_cancel.py`。

### 3.4 六场景覆盖对照

| 赛题场景 | 主/辅 | 现状 | 本次改造后 | 证据 |
|---|---|---|---|---|
| 1 智能转账 | 辅 1 | 已实现 | 不变 | `test_e2e_transfer.py`、`test_split.py` |
| 2 账单分析 | 辅 1 | 已实现 | +分类占比图 | `bill.py`、`test_tools.py` |
