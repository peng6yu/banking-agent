## 2. 六栏功能清点（要点版）

> 完整 109 行见侦察原始表；这里只留「用户会点到的功能 + 最该打的边界值」。

### 2.1 财务总览（#view-overview）
余额卡（主账户 12860.50 元 / 副文案说「不代表待执行后余额」）、本月支出、本月收入、近期收支三行（结余「不含转账/理财」）、分类占比（最多 6 类）、异常前 3 条 + 「还有 N 条」、待处理授权（批准/拒绝/就地验证/去完成验证/已过期）、储蓄目标前 3、近期计划与提醒（预约 3 + 预警 2 + 调度器一行）、人工接管最多 6、5 个 AI 快捷 chip、脚注（暂不可用列表 + 数据生成时间）。

关键边界：账户缺失回退 accounts[0]；本月 0 支出显示「0.00 元」；`net_yuan=abs(net)` 亏损显示正数；`more_count=max(0,len-3)`；`expired` 由 `expires_ms<=now` 派生；无 `confirmation_id` 不出按钮；`#ov-plans` 的「立即执行到期任务」按钮在**计划页**而不在总览（文案指路落空）。

### 2.2 账单分析（#view-bill）
月/年切换（无选中态、选不了历史年月）、刷新（只清 bill 缓存）、汇总三卡（净结余=前端 in-out，含转账/理财）、分类占比（无口径说明）、趋势表 6 月（当月「未完」、金额无「元」后缀、结余无正负）、异常卡片（3 条规则：R-BILL-01 拆单 60 分钟内 ≥3 笔且单笔 500–1000 元 / R-BILL-02 凌晨 00–05 点境外且 ≥500 元 / R-BILL-03 连续两月涨 ≥30%）、异常动作（查看流水/AI 解释/冻结卡/看订阅）、相关流水表（只汇总 evidence，不是对账单）、手动记一笔表单（商户 40 / 分类 12 / 备注 80）。

关键边界：`bxYuanToFen` 用 `/[^0-9.]/` 过滤 → `-50` 变 `+50`；全角数字 → 0 → 同一句「金额要写大于 0 的数」；`12.345` → 12.35；422 的 `detail` JSON 会原样进气泡；同日幂等键含备注/分类；支出方向才校验余额且只查账面 `balance_fen`；渠道固定 `manual`。

### 2.3 AI 助手（#view-assistant）
发送（SSE）、工具清单、四面板（意图/计划/策略/因子）、澄清 chips、同名收款人候选、确认卡（金额/收款人/等级/确认号）、多因子、中断、刷新恢复、历史与技术面板、500 字上限。

关键边界：`CONFIRM_TIMEOUT_S` 10–3600 可覆盖（默认 120s，状态机在 app/planner/state.py:35-72）；`CHALLENGE_TTL_MS=300000`、`MAX_ATTEMPTS=5`、`FACTOR_DEMO_ECHO` 默认开（关闭后无渠道即 fail closed）；`CLARIFY_TTL_MS=300000` 且进程重启即失效；`/api/session/{sid}/recover` 无 UI 入口。

### 2.4 计划与提醒（#view-plans）
调度器横幅（enabled && running 才算在跑）、目标、计划任务、即将到期、最近执行、生日计划（预算 1000 / 鲜花 400 / 蛋糕 600，商户只有两家）、跨场景计划、提醒（文本/时间/重复 daily|weekly|monthly）、主动财务（储蓄目标 CRUD、监测、预警忽略/解决、注入模拟支出 88 元）。

关键边界：生日预算超 `MAX_TARGET_FEN`（≈1 亿）→ 422 原文「建生日计划失败：…」；提醒过去时间静默滚到明天 09:00；monthly 31 号在 2 月钳到月末（app/reminder_time.py:37-39）；`plan_hooks` DUE_KEYS = checked/paid/skipped/needs_verification/revoked/expired；注入支出会真实进告警链路。

### 2.5 业务管理（#view-manage）
卡片表（2 张 active：尾号 1234 限额 5000 / 5678 限额 2000）、卡片动作（冻结/解冻/调限额/挂失，全部 `bxAsk`）、订阅与代扣（爱奇艺 25/月、百度网盘 12/月、网易云 15/月、乐刻 199/月、Office365 99/年）、停代扣、疑似订阅（≥3 笔、间隔 25–35 天或 350–380 天、spread ≤1.25、最多 10 条）、定性（not_subscription/confirmed，可撤回）、逐笔核对、已定性/已停止两区、近 7 天可能扣费（seed 的 next_charge=now+30 天 → 默认空）、长期记忆（GET 上限 50、key 1–40、value 1–200）、理财产品表（`duration_days/liquidity/fee` 刻意 None）、适当性标签、5 题问卷（0–15 分，档位 0/4/8/12/14）、能力与边界 6 项。

关键边界：`subscription_verdicts` 是全项目唯一「用户定性 + 可撤回」闭环；停代扣只停银行侧、商户会员仍在；「月合计 251 元」不含年付；未评估也能点「买」（后端拒）；`capabilities.investment.notes` 仍写「没有适当性问卷」，与真实下发的 5 题矛盾。

### 2.6 执行记录与安全（#view-security）
三张汇总卡、会话九态、人工接管队列（pending/claimed/need_info → rejected/cancelled/resumed/failed，12 个固定错误码 + 中文 user_text）、领取/拒绝/补信息/恢复、拒绝记录、审计链拉取 + 校验 + 篡改检测、安全边界文案。

关键边界：部分唯一索引保证同 run 只有一张活单；handoff 读取异常被吞成空列表（app/views/queue.py:182）→ 前端分不清「空」与「坏」；审计事件是 **frozenset 闭集**（app/audit.py:24-128），写入未知事件会被拒。

## 4. 三组口径矛盾（写断言时优先锁这三条）

1. **结余**：总览 = `_trend.net`（不含内部搬运）；账单净结余 = 前端 `total_in - total_out`（含转账/理财）；趋势表 = `_trend.net` 但 `abs()`（无符号）。
2. **余额**：`balance_fen`（账面）vs `held_fen`（hold，TTL 5 分钟）vs `reserved_budget_fen`（plan_budgets status='reserved'；'paying' 不计）。页面只展示账面。
3. **空态**：overview/bill 异常区空态标题都取后端 `state`，而 `state='发现异常（待核实）'`。

## 5. 消息互联互通：现有基座与缺口

**已有的五个「准消息」**

| 来源 | 表/机制 | 状态机 | 缺什么 |
|---|---|---|---|
| 预警 | `proactive_alerts`（app/db.py:334-344） | open → ignored/resolved，只进不退 | read_at / dismissed / severity / title / deep_link |
| 异常 | 实时计算，**无表** | 无 | id 是数组下标（money.py:102）→ 不能当主键 |
| 待确认 | `confirmations` | pending/approved/rejected/expired（过期靠派生） | 无「已读」 |
| 疑似订阅 | 实时推断 + `subscription_verdicts` | 唯一「用户定性 + 可撤回」闭环 | 无 dismiss / 无提醒 |
| 人工接管 | `handoffs` | 6 态 + 12 错误码 | 无用户「已读」，只有操作员动作 |

**唯一广播点**：`app/plan_hooks.py` 的 DUE_KEYS（checked/paid/skipped/needs_verification/revoked/expired）——仅进程内、无持久化、无订阅者即静默。

**要建统一消息中心，缺**：1 张 `messages` 表（id/user_id/kind/severity/title/body/source_table/source_id/deep_link/created_ms/read_ms/dismissed_ms/acted_ms/expires_ms/dedupe_key）、1 张 `message_feedback`（action: adopt/dismiss/snooze/never）、6 个字段回填到现有表、6 个端点（list/read/dismiss/adopt/count/snooze）、4+ 审计事件（notification.created/read/dismissed/adopted——注意审计是闭集，必须显式加进 EVENT_TYPES）、4 个前端位置（总览今日建议、栏目内联卡、消息中心、侧栏未读角标）、1 个深链协议（`view=` + item id；现有 `anchor` 只是 6 类业务标签，app/scope.py:129-138，**不是跳转锚点**）。

**复用现成的**：`subscription_verdicts` 的「定性—撤回」交互、`confirmations` 的 TTL/幂等、`handoffs` 的中文错误码表、`plan_hooks` 的事件点。

## 7. 与本计划主文档的差异（口径修正）

- 端点/tool 数量：主文档写「47 条 API 路径 / 35 个工具」，实测 `app/tools/tool_specs.py` 是 **19 个 tool spec**、业务端点是 **35 条**；47 是 release_manifest 的路由口径。体检时以**实测**为准，并把口径差异本身记为 P3 文档缺陷。
- UI 功能点：主文档六栏表 51 行，附录 A3 拆到 **58 个功能点**（差异来自总览/管理/安全拆得更细）。
- 截图脚本入口：主文档写 `scripts/ui_screenshots.py`、`ui_journeys.py` 可直接跑；实际 `make` 无 target，须显式 `.venv/bin/python scripts/xxx.py`。
