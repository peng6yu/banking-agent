## 附录A. 一句话结论

底层数据是干净的：金额一律存分、时间一律存毫秒、结构化内容一律存 JSON 文本、主键一律带前缀、命名违规自动检查 0 条。
**乱在「出口」——同一个概念在不同接口有 2-5 种形状，前端只能各自兜底。**所以「把所有数据搞清楚」的落点不是再盘点一遍字段，而是给每个概念定一个形状、一个落点，然后让所有出口都吐它。

> **2026-10-26 深夜第三次收口（「全都修」）**：剩下的 5 条也做完了——会截断的三个列表（`/api/audit`、`/api/handoffs`、`/api/chat/latest`）已带 `total`；4 处路由自拼 SQL 全部搬进已有视图（`views/executions.session_detail_view` / `audit_trail_view`、`views/management.memory_view`、`views/queue.handoff_list_view` / `handoff_detail_view`），路由只剩薄壳且没有新建模块；生日计划 meta 由 `app/plans.py:_meta_view` 补 `budget_yuan`，页面最后一处 `/100` 已删；A2 复核为「键存在、无账户时值为 None」并用测试钉住；F4 只对 `/api/handoffs` 列表做白名单投影（`dag/failure/auth` 等库内 JSON 不再直出），单张详情保留给操作员。

## 附录C. 单位与量纲（对外契约）

- 金额：DB 存**分**（`*_fen`，INTEGER），接口**成对**给 `*_fen` 与 `*_yuan`（字符串，千分位两位小数），页面**只渲染 `*_yuan`**，禁止再 `/100`。页面里最后一处 `/100`（`web/js/88-view-monitor.js:75`）已在本轮删除。
- 时间：DB 存**毫秒**（`*_ms`，UTC 毫秒，按服务器本地时区解释），接口成对给 `*_ms` 与 `*_text`。
- 百分比：`*_pct` 为整数百分比（52 表示 52%），不存 0.52。
- 比例/占比：页面本地算，不落库、不进接口。
- 条数：只给「本页条数」，字段名必须自证（见上表计数行）。

## 附录F. 仍然不清楚的部分（诚实清单）
