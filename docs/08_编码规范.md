# 08 编码规范

> 目标：三个不同模型先后接手，产出的代码看起来像**一个人写的**。所有条款都是硬要求，Code Review 按此表逐条过。

## 8.1 语言与依赖

| 项 | 规定 |
|---|---|
| Python | 3.11 或 3.12（**不要 3.14**，本机 /usr/bin/python3 是 3.14，必须用 `python3.11`） |
| 虚拟环境 | `banking-agent/.venv`，用 `uv venv` 或 `python3.11 -m venv` |
| 依赖清单 | `requirements.txt` 锁死版本（`==`，不用 `>=`） |
| 允许的第三方库 | 仅：`fastapi`、`uvicorn`、`pydantic`、`httpx`、`pytest`、`pyyaml`。**其他一律先问** |
| 禁止引入 | `langchain`、`langgraph`、`openai` SDK、`sqlalchemy`、`requests`、`celery`、`redis` |
| 数据库 | 标准库 `sqlite3`，不引 ORM |
| 前端 | 单文件 HTML + 原生 JS，**不引框架、不引 CDN** |

禁止 ORM / LangGraph 的理由：审计链要逐字段可控，ORM 的隐式行为会让哈希材料不可预测；LangGraph 的图状态会藏住「谁在什么时候决定了什么」，而我们整个作品的卖点就是**这条链路完全可见**。

## 8.2 命名

| 类别 | 规则 | 示例 |
|---|---|---|
| 模块/文件 | 全小写 + 下划线 | `policy_engine.py` |
| 函数/变量 | snake_case | `issue_token`, `amount_fen` |
| 类 | PascalCase | `PolicyEngine`, `ToolResult` |
| 常量 | UPPER_SNAKE | `YELLOW_LIMIT_FEN` |
| 私有 | 前缀单下划线 | `_verify_hmac` |
| **金额** | 必须以 `_fen` 结尾 | `amount_fen`, `balance_fen` |
| **时间** | 毫秒整数以 `_ms` 结尾 | `created_ms`, `expires_ms` |
| 错误码 | UPPER_SNAKE 字符串 | `INSUFFICIENT_FUNDS` |
| 审计 event_type | `域.动作` 小写点分 | `policy.decided` |
| CSS 类名 | 短横线 | `panel-policy` |

`_fen` / `_ms` 后缀是**强制**的。看到不带后缀的 `amount` 或 `time`，Review 直接打回 —— 这是唯一能防住单位混用的手段。

## 8.3 类型与结构

| 要求 | 说明 |
|---|---|
| 所有公开函数必须有类型注解（参数 + 返回值） | 没有注解的打回 |
| 数据结构用 `pydantic.BaseModel` 或 `dataclass` | 禁止用裸 dict 在模块间传递 |
| pydantic 模型一律 `model_config = ConfigDict(extra='forbid')` | 多传字段要报错，不能静默忽略 |
| 函数体 ≤ 50 行，超了就拆 | 便于单测与 Review |
| 圈复杂度：一个函数内 `if/elif` 分支 ≤ 8 个 | 超了说明该用规则表 |
| 单文件 ≤ 400 行 | 超了拆模块 |

## 8.4 错误处理

**唯一允许的做法**：抛出 `app/clock.py` 里定义的业务异常，由 API 层统一转 HTTP。

```python
# 正确
if balance_fen < amount_fen:
    raise InsufficientFunds(short_fen=amount_fen - balance_fen)

# 错误：返回 None 让上层猜
if balance_fen < amount_fen:
    return None
```

| 禁止 | 原因 |
|---|---|
| `except Exception: pass` | 审计会失真 |
| `except:` 裸捕获 | 同上 |
| 捕获后 `print` 了事 | 必须 `log.error` + 要么重抛要么返回结构化失败 |
| 把英文异常名直接返给用户 | 体验分要扣，必须映射成中文 `user_text` |
| 500 响应里带 `traceback` | 安全分要扣 |

业务异常类清单（`app/clock.py` 里统一定义）：`BankError`（基类，含 `code` 与 `user_text`）→ `ValidationError`、`PolicyDenied`、`MissingCapability`、`TokenExpired`、`TokenMismatch`、`InsufficientFunds`、`HoldExpired`、`InjectionDetected`、`BreakerOpen`、`ToolNotFound`。

## 8.5 时间、随机与金额

| 规则 | 原因 |
|---|---|
| 时间只能通过 `app/clock.py` 的 `now_ms()` 拿 | 便于测试注入假时钟 |
| **禁止** `datetime.now()`、`time.time()` 直接出现在业务代码 | 同上，Review 打回 |
| 随机只能通过 `app/ids.py` 的 `new_id()` / `nonce()` | 便于固定种子复现 |
| 金额全程 `int`（分） | 浮点误差会算错钱 |
| 展示时才用 `money.fen_to_yuan_str()` | 只在出口格式化 |

## 8.6 日志与审计（两套，别混）

| | 日志 `app/log.py` | 审计 `app/audit.py` |
|---|---|---|
| 给谁看 | 开发者 | 用户 / 评审 / 合规 |
| 存哪 | stderr | `audit_log` 表，哈希链 |
| 可变 | 可变 | **只增不改** |
| 内容 | 异常堆栈、耗时、上下游 id | 决策与执行的事实 |
| 禁止 | 写金额明文？可以写 | 写堆栈？**不行** |

日志用结构化字段输出一行 JSON：`log.info('tool.exec', node_id=..., ms=...)`。**不要 f-string 手拼 JSON**。

## 8.7 注释

| 要求 | 说明 |
|---|---|
| 文件头必须有模块 docstring | 一句话说明这个文件干什么 |
| 注释解释**为什么**，不解释**做什么** | `# 先查余额再签发 token，否则可能出现已签发但余额不足` |
| 中文注释 | 全项目统一中文 |
| 与文档对应的实现处标文档号 | `# 见 docs/05_安全层实现规格.md 5.3` |
| 禁止注释掉的死代码 | 删掉，git 里有历史 |

文件头模板：

```python
"""安全层：三色裁决与能力令牌。

对应文档：docs/05_安全层实现规格.md
"""
```

## 8.8 导入顺序

```python
# 1. 标准库
import hashlib
from typing import Any

# 2. 第三方
from fastapi import APIRouter

# 3. 本项目
from app.clock import now_ms
from app.policy.engine import decide
```

禁止循环导入。若出现，说明依赖方向错了 —— 见 `docs/01_架构与数据流.md` 的模块依赖表，**改结构而不是加 `TYPE_CHECKING` 掩盖**。

## 8.9 前端代码规范

| 要求 | 说明 |
|---|---|
| 全部包在 `(function(){ ... })()` 里 | 不污染全局 |
| `const` 优先，禁止 `var` | — |
| 所有后端字符串过 `escapeHtml()` | 防 XSS |
| DOM 更新用 `textContent` 优先 | 只有需要结构时才 `innerHTML` |
| fetch 的错误必须 try/catch 并显示人话 | 不许静默失败 |
| 前端不写业务判断 | 颜色/级别一律来自后端 |

## 8.11 写作规范（文档与答辩文案）

| 要求 | 说明 |
|---|---|
| 中文全角标点 | 逗号句号用「，」「。」 |
| 数字与单位之间不加空格 | 1000 元 |
| 术语首次出现给英文 | 能力令牌（capability token） |
| 表格优先于长段落 | 评审只有 10 分钟 |
| 不写形容词堆砌 | 写「1000 元以下黄色」不写「智能分级管控」 |
| 每个设计决策必须带**理由** | 无理由的设计在答辩时会被问死 |
