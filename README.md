# 银行 AI 智能体（Banking Agent）

> 2026 金融科技大赛 · 人工智能赛道 · 国内赛道
>
> **一句话**：别人在做更聪明的银行助手，我们在做**银行敢让它动钱的 Agent**。

## 这是什么

一个能替用户在手机银行里真实办事的 AI 智能体：理解中文金融意图 → 拆解成可执行的 DAG → 每步经过**确定性权限闸门**裁决 → 高风险动作要求人工确认与多因子验证 → 全链路写入**不可篡改的审计哈希链**，并在前端实时呈现。

覆盖三个场景：

| 场景 | 能做什么 |
|---|---|
| 智能转账 | 按姓名/备注转账，口语金额（五百五、全部），同名多收款人区分，超线自动升级验证 |
| 账单分析 | 月度/年度统计、分类占比、三类异常识别（短时拆单、境外深夜大额、订阅涨价） |
| 跨场景联动 | 「下周三我妈生日帮我准备」→ 查人 → 查余额 → 锁定预算 → 下单鲜花，支持中断与回退 |

## 核心设计：三段论

```
用户输入                    ┌─────────────┐
   │                        │ 不可信区     │  LLM 只产出「申请」
   ├─► 数据信封 ──────────► │ 意图 / 规划  │  不产出「执行」
   │   (<DATA> 隔离)         └──────┬──────┘
   │                                │ Action
   │                        ┌──────▼──────┐
   │                        │ 裁决区       │  纯函数，无网络无模型
   │                        │ PolicyEngine│  绿/黄/红 + 能力令牌
   │                        └──────┬──────┘
   │                                │ capability_token
   │                        ┌──────▼──────┐
   │                        │ 执行区       │  只认令牌，无令牌即拒
   │                        │ Tools + 资金 │  两阶段提交，可补偿
   │                        └──────┬──────┘
   │                                │
   └──────── 决策剧场（SSE 实时）◄──┴──► 审计哈希链（只增不改）
```

### 四个承重墙

| # | 设计 | 一句话 |
|---|---|---|
| 1 | **权限闸门是代码不是 prompt** | 即使 LLM 100% 被劫持，执行器没有合法令牌就动不了一分钱。现场可换恶意 mock 演示 |
| 2 | **资金两阶段提交** | hold → commit，幂等键 + 超时释放，不产生「扣了钱没转账」的中间态 |
| 3 | **决策剧场** | 把不可见的安全层做成可见的实时侧栏（意图→DAG→三色灯→因子→审计） |
| 4 | **信任边界显式化** | 交易备注、商户名、IM 转发一律当数据不当指令，带签名信封隔离 |

## 三色权限

| 灯 | 范围 | 处理 |
|---|---|---|
| 绿 | 纯查询（余额、流水、账单、订阅、卡片） | 自动执行 |
| 黄 | 小额转账（日累计 ≤ 1000 元）、取消订阅 | 用户点一次确认 |
| 红 | 大额转账（日累计 > 1000 元）、改密码、挂失 | 人脸 + 短信 + 一次性口令，多因子 |

边界写死：999.99 黄 / 1000.00 黄 / 1000.01 红；今日已转 900 元再转 200 红、再转 100 黄。

## 5 分钟跑起来

```bash
# 0. 确认解释器（本机固定用系统 python3.12，已装好全部依赖）
python3.12 --version

# 1. 密钥（从本机已有配置抽取，不手抄）
bash setup_env.sh

# 2. 建库 + 种子数据
make seed

# 3. 起服务
make run
# 打开 http://127.0.0.1:8000
```

> 换机器时才需要装依赖：`python3.12 -m pip install fastapi uvicorn pydantic httpx pyyaml pytest`。
> 本机 pypi 直连 DNS 不稳，**不要**建 venv 再 `pip install -r requirements.txt`，会失败。
> 异步测试用 `asyncio.run()`，不依赖 pytest-asyncio。

## 技术选型（为什么这么选）

| 选择 | 理由 |
|---|---|
| 运行时模型 MiniMax-M3.1-Flash-Preview（云端） | 实测 1.56s、5/5 稳定、不吐思维链；本机 GPU 驱动异常不可用，4GB 可用内存跑不动 7B |
| 不用 LangGraph / 多 Agent 框架 | 审计链要逐字段可控；多 Agent 会糊掉责任边界，金融场景要单点可追溯 |
| 结构化输出只走 tool_calls | 实测 MiniMax 的 `response_format: json_object` 不被遵守，会只吐 think 不吐 JSON |
| SQLite + 标准库 | 零运维，评审可一键复现；审计表用触发器禁改 |
| 单文件前端 | 断网也能演示 |

详见 `规划/00_选型决策_本地vs云端.md` 与 `规划/05_MiniMax接入实测.md`。

## 安全声明

本项目为比赛演示原型：**所有银行数据均为本地种子生成的虚构数据，不连接任何真实银行系统，不发起真实支付**。模型密钥仅从本机环境变量读取，不入库不入仓。
