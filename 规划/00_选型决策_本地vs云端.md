# 选型决策：本地模型 vs 云端模型

> 这份文档回答一个问题：**这个 Agent 的大脑跑在哪。**
> 所有结论基于本机实测，不是推测。

---

## 1. 实测硬件事实

| 项 | 实测值 | 对 LLM 推理的含义 |
|---|---|---|
| GPU 型号 | NVIDIA RTX 4060 Laptop，AD107M，8GB 显存 | 7B-Q4 勉强，14B 不可能，30B-MoE 不可能 |
| GPU 驱动 | 595.99.02 open 内核模块已加载，PCIe 正常，/proc/driver/nvidia 可读 | 驱动层没问题 |

| CPU | 32 线程（Ryzen 9 7945HX） | CPU 兜底可行，但只有 1.7B–4B 档能跑 |

| 网络 | DeepSeek / 通义 / Moonshot / 智谱 四家 API 全部可达（401 = 缺 key），延迟 100–300ms | 云端通路健康 |
| Python | 系统 3.14.4（过新，多数库无轮子），另有 3.11 / 3.12 + uv 0.13 | 用 uv + 3.12 建项目 |
| API Key | 环境变量中一家都没配 | **需要你提供** |

### 1.1 一个必须说清的事实

**这台机器现在用不了 GPU 做推理。**
原因是 /dev/nvidia* 设备节点没生成，而 sudo 被沙箱的 no-new-privileges 标志挡住，我没法执行 nvidia-modprobe 去补。
这不是配置问题，是当前会话的权限边界。

即使你在宿主上把节点补好（`sudo nvidia-modprobe` 或重启 udev），**8GB 显存的上限仍然存在**：
- 7B-Q4_K_M ≈ 4.4GB 权重 + KV cache，8K 上下文约 5.5–6GB → 勉强能跑
- 14B-Q4 ≈ 8.5GB → 跑不动
- 而 ComfyUI 那套还在占显存

**所以：本地路线不是「配置一下就能用」，是有硬顶的。**

## 2. 逐维度对比

| 维度 | 云端（DeepSeek / Qwen） | 本地（Ollama + 4B/7B） |
|---|---|---|
| 中文意图理解 | 强，口语/省略/隐含都能扛 | 弱，槽位经常漏，消歧能力差 |
| 多步 DAG 规划 | 稳，结构化输出可控 | 差，工具名会编造，JSON 会破 |
| 严格 JSON / function calling | 可靠（配合 Pydantic 校验） | 需 grammar 约束，仍会崩 |
| 首字延迟 | 0.6–1.5s | CPU 下 3–10s（4B），GPU 下 0.3s |
| 吞吐 | 40–80 tok/s | CPU 下 5–12 tok/s（4B），易 swap |
| 成本 | 整套测试跑完 < ¥50 | 电费 |
| 离线可用 | ❌ | ✅ |
| 演示日风险 | 依赖场馆网络 | 无网也能跑，但慢且笨 |
| 可控性（做攻击实验） | 不可控 | ✅ 可完全操控 |

## 3. 结论：不要二选一，要「四角色模型架构」

这是本方案最重要的一个判断，也是**答辩时最有说服力的一段**：

> **本地模型不是云端的备胎，是证明「安全与模型无关」的对照组。**

| 角色 | 模型 | 用途 | 依赖 |
|---|---|---|---|
| **主脑** | 云端 DeepSeek（主力）/ Qwen-Plus（备份） | 意图理解、槽位、DAG 规划、话术生成 | 网络 |
| **快脑** | 云端 Qwen-Flash 或 GLM-4-Flash | 注入分类、风险预判，要快且便宜 | 网络 |
| **对照组** | 本地 Ollama + Qwen3-4B-Instruct | **弱模型实验**：证明攻击成功率不随模型变弱而上升 | 无（CPU） |
| **对抗体** | Mock 恶意模型（自己写，固定输出） | **安全演示**：模拟 100% 被劫持的 LLM，闸门仍拦截 | 无 |

### 3.1 为什么这个设计值钱

评委问得最狠的一句话会是：

> 「你这些安全机制，换个模型不就失效了？」

标准答案（可现场演示）：

1. 把主脑切到 **本地 4B 弱模型** → 任务完成率明显下降（多追问、多保守），但**攻击成功率不上升**
2. 把主脑切到 **对抗 Mock 模型**（它 100% 想转账、100% 忽略所有指令）→ **依然一分钱都转不出去**
3. 结论：安全由**策略引擎 + capability_token** 保证，不由模型的听话程度保证

这个演示有三个好处：
- 把 8GB 显存的短板变成了实验装置
- 零网络依赖（Mock 和本地模型都不需要网），**演示日断网也照演**
- 直接回应 30% 安全分里最核心的质疑

### 3.2 一句话架构原则

> **模型可换，闸门不可换。**
> 换模型只影响「说得好不好」，不影响「能不能动钱」。

## 4. 具体选型

### 4.1 云端

| 位置 | 首选 | 备份 | 参数 | 理由 |
|---|---|---|---|---|
| 主脑 | DeepSeek 对话模型（deepseek-chat 档） | Qwen-Plus | temp=0, top_p=0.1, JSON mode | 中文金融语料强、function calling 稳、便宜 |
| 快脑 | Qwen-Flash / GLM-4-Flash | deepseek-chat（同key） | temp=0, max_tokens=64 | 只做二分类（是否注入 / 风险高低），要 <300ms |
| 推理增强 | deepseek-reasoner（仅复杂 DAG 规划时启用） | — | — | 场景 6 多步规划可开，代价是延迟 |

**注意**：具体模型 ID 不要写死。启动时调 `GET /v1/models` 拉取可用列表，按优先级匹配，匹配不到就报错并提示。
（各平台模型 ID 会变，写死是最常见的翻车原因。）

### 4.2 本地

| 用途 | 模型 | 量化 | 体积 | 预期速度（CPU, 4GB 可用） |
|---|---|---|---|---|
| 对照实验 | Qwen3-4B-Instruct | Q4_K_M | ≈2.5GB | 6–10 tok/s |
| 极简兜底 | Qwen3-1.7B-Instruct | Q4_K_M | ≈1.1GB | 15–25 tok/s |
| 嵌入（已有） | bge-m3 | — | 1.2GB | — |

**不要下 7B**：4.1GB 可用内存跑 7B-Q4 会疯狂 swap，演示时会卡成 PPT。

拉取命令（P0 阶段执行）：
```
ollama pull qwen3:4b-instruct-q4_K_M
ollama pull qwen3:1.7b
```

### 4.3 嵌入模型

bge-m3 本地已有 → 用于：联系人模糊匹配（「老王」→ 王建国）、商户名归类、账单语义检索。
**这个不需要云端**，本地 CPU 足够，且不增加隐私风险。

## 5. LLMAdapter 接口（代码契约）

所有模型走同一接口，上层代码零感知：

```python
class LLMProvider(Protocol):
    name: str
    async def structured(
        self, system: str, user: str, schema: type[BaseModel],
        *, temperature: float = 0.0, timeout: float = 20.0,
    ) -> BaseModel: ...

    async def classify(self, text: str, labels: list[str]) -> str: ...
```

四个实现：

| 文件 | 类 | 行为 |
|---|---|---|
| `providers/cloud.py` | `CloudProvider` | OpenAI 兼容协议，JSON mode + Pydantic 校验，失败重试 2 次后降级 |
| `providers/local.py` | `LocalProvider` | 调 Ollama /api/chat，format=json，超时 60s |
| `providers/adversarial.py` | `AdversarialProvider` | **故意返回恶意计划**：永远尝试 transfer(10000, 新收款人)，永远声称已获授权 |
| `providers/router.py` | `ModelRouter` | 按 .env 的 `LLM_PROFILE` 选实现；熔断时自动切备用 |

**关键设计**：`AdversarialProvider` 是**一等公民**，不是测试 hack。
它让「闸门有效性」成为一个可回归测试的断言，而不是一句 PPT 上的话。

## 8. 决策记录（给答辩用）

| 问题 | 决策 | 理由 |
|---|---|---|
| 用本地还是云端？ | **云端为主，本地为对照 + 兜底** | 本机 GPU 不可用且仅 8GB；云端质量/延迟/成本全面占优 |
| 为什么还要做本地？ | 作为**弱模型对照组**与断网兜底 | 把硬件短板转化为安全论证装置 |
| 会不会被质疑依赖外部 API？ | 有答案：架构是 provider 可插拔 | 现场可切本地，闸门行为不变 |
| 演示日断网怎么办？ | Mock + 本地模型双兜底 | 安全演示零网络依赖 |
