# 单人版落地方案（含 MiniMax 模型方案调整）

> 前置结论：**一个人做完是可行的，但不能按三人版的范围做。必须砍到 1/3，并且把编码工作交给 AI。**
> 本文替代 03_排期与分工.md 中的三/五人排期。

## 0. MiniMax Coding Plan 怎么用

### 0.1 事实

| 项 | 内容 |
|---|---|
| 价格 | 基础版首月 9.9 元，之后 29 元/月 |
| 给的模型 | MiniMax-M2.1，负载低时自动给更快的 lightning 版本 |
| 配额 | 约 40 次提示 / 5 小时 |
| 定位 | 给 Claude Code / Cline / Cherry Studio 这类编程助手用的订阅 |

### 0.2 关键判断：这是两件不同的事，不要混

| 用途 | 该用什么 | 为什么 |
|---|---|---|
| 你写代码时的 AI 助手 | **MiniMax Coding Plan，买** | 29 元/月，比按量付费便宜一个数量级，一个人开发更该买 |
| 你的 Agent 运行时调用的模型 | **开放平台按量付费** | 红队 20 条 × 每条约 4 次调用 = 80 次以上，加回归测试轻松上千次；40 次/5 小时的配额半天就烧穿 |

结论一：Coding Plan 买，用来加速你写代码，这是纯赚。
结论二：业务侧走开放平台按量付费，整个项目周期不到 200 元，这点钱不值得省。
结论三：如果 Coding Plan 的 key 在开放平台端点也能用，先试。但必须实测：跑一次 20 条红队，看会不会 429 或明显变慢。会，就切按量。

### 0.3 主脑用 MiniMax-M2.1 行不行

**行。** M2.1 是 MoE 架构，工具调用与结构化输出都支持，中文也够。

但要注意分工：

| 维度 | 判断 |
|---|---|
| 结构化 JSON 输出稳定性 | 可用，但要在适配层加重试与 schema 校验 |
| 中文金融意图 | DeepSeek 与 Qwen 语料更对口，MiniMax 略弱 |
| 工具调用 | 支持，长 DAG 规划能力中等 |
| 影响评分吗 | **影响完成率（40%），不影响安全分（30%）** |

这正是「模型可换，闸门不可换」的价值：**主脑换成任何模型，安全分都不掉。**

**建议配置**：

| profile | 实际用什么 | 用途 |
|---|---|---|
| cloud | 主选 DeepSeek-V3 或 Qwen-Plus；备选 MiniMax-M2.1 | 业务主脑 |
| fast | Qwen-Flash 或 GLM-4-Flash | 注入分类 |
| local | Ollama qwen3:4b | 弱模型对照 |
| adversarial | 自己写的 mock | 被劫持演示 |

只有 MiniMax 的 key 也能全跑，把 cloud 指向 MiniMax 即可，改 .env 一行。

## 1. 一个人的算力账

| 方案 | 人日 |
|---|---|
| 原计划（3 人 × 14 天） | 约 42 人日 |
| 你一个人 14 天 | 14 人日 |
| 缺口 | **差 3 倍** |

三个动作补上这个缺口：

1. **砍横向**：场景从 5 个降到 3 个（题目下限），工具从 20 个降到 10 个。
2. **砍工程复杂度**：前端从 React+Vite 改成单文件 HTML 加原生 JS 加 SSE，去掉构建步骤，省 2 天。
3. **把编码交给 AI**：你负责决策、验收、演示；代码由 AI 生成，你只做 code review 和调试。这是唯一能补上 3 倍缺口的办法。

## 4. 单人的三个真实优势

别只看缺口，单人也有好处，答辩时可以讲：

1. **没有联调成本。** 三人版最容易死的地方是接口对不齐。
2. **叙事统一。** 一个人做出来的东西，从定位到实现到话术是一条线，评委感受得到。
3. **决策速度快。** 遇到取舍当场拍，不用开会。
